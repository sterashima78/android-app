# 4. コンテンツ閲覧と整理

## 4.1 RSS

- RSS / Atom 系フィードを登録して記事を取得する。
- 未読、既読、履歴を管理する。
- フィードの追加、削除、手動更新、OPMLインポートを提供する。

- RSS画面の初期表示では端末内に保存済みのフィード・記事を直ちに表示する。画面表示時の自動取得間隔と取得失敗後の再試行間隔はRSS設定タブで変更する。前者の既定は30分で1分から7日までの選択肢を持ち、後者の既定は5分で1分・5分・15分・30分・1時間から選択できる。
- フィード管理の各購読フィードとRSS設定タブのWeb取得ルールに任意の自動取得間隔を設定できる。未指定なら継承する。自動取得時の適用順は「購読フィード固有設定 > URLに一致する最も具体的なWeb取得ルールの設定 > 取得契機の共通設定」とする。自動取得は前回成功した取得（HTTP 304を含む）から有効間隔を経過したフィードだけ実行する。例えば共通1時間・フィード固有3時間の場合、取得から3時間未満は画面・周期更新とも再取得しない。手動強制取得とインポートは間隔と失敗後の再試行抑制を適用しない。
- 複数画面・周期更新・ウィジェット等から同じフィードの更新が重なった場合、通信は1件ずつに統合する。ウィジェットの自動更新も個別取得間隔を尊重するが、利用者が明示したウィジェット更新ボタンは強制取得する。RSS更新中の状態は画面間で共有する。OPMLインポート直後に未取得のフィードは、自動更新の初回取得対象に含める。
- 通常の登録済みフィードのHTTP更新について、端末内の通信量診断へ受信本文byte数、取得試行回数、HTTP 304回数と取得契機（画面表示・手動・定期・インポート）を記録する。通信量診断には指定期間・回線の受信量上位10フィードを表示し、現在登録されているフィード名を参照する。フィード別診断のために記事本文やURLを保存せず、WebViewスクレイピングはフィード別転送計測の対象外とする。
- コンテンツ取得や分類は source 固有情報を維持しつつ Content Context へ接続する。
- RSS設定では「読みたい必要性が低い記事」の手動条件と、優先・除外参考から学習した両方向の条件を利用する。推薦評価と両条件の同時学習の実行先は端末内AIまたはクラウドAIから明示選択でき、既定は端末内AI、自動fallbackはしない。いずれかの条件がある場合、未読記事のタイトルだけを構造化tool callへ入力し、評価可能な記事を1〜10の読みたい優先度として表示する。1は低優先、10は高優先を表す。
- 推薦条件が有効で、まだ現在revisionの評価結果がない未読記事は「推薦: 評価待ち」と表示する。評価完了後は数値または未評価理由へ置き換える。タイトルだけでは条件との関係を判断できない記事は数値を付けず「タイトルだけでは判断できない」と表示する。推論またはtool call検証に失敗した記事も数値を付けず、判定失敗として区別する。優先条件と除外条件が競合しタイトルだけでは解消できない場合も数値化しない。どちらの条件も空の場合はスコアリングを行わない。
- RSSの未読一覧は、現在の推薦条件で確定したスコアがある記事をスコアの高い順に優先表示する。同じスコアの記事は公開日時の新しい順 / 古い順を切り替えて表示し、スコアなし（評価待ち・未評価）の記事は数値評価済み記事より後ろで同じ日時順に並べる。推薦条件が無効なら日時順だけで表示する。既定は新しい順とする。
- 未読一覧では通常の左スワイプを「既読」、深い左スワイプを「除外参考」とする。通常左は短めの操作で確定し、除外参考はカード幅に対して明確に深くスワイプした場合だけ選択される。通常左から深い左へ切り替わる境界では表示と触覚フィードバックで操作の変化を伝える。「除外参考」は記事を既読にしたうえで、そのタイトルと直前の推薦評価を今後の除外条件改善用feedbackとして保存する。右スワイプの「ブックマーク」と深い右スワイプの「あとで読む」は従来どおり維持する。RSS記事を「あとで読む」へ新規追加できた場合は、同じ記事を優先参考としても登録し、既存の学習待ちキューへ通知する。「あとで読む」の保存に失敗した場合は優先参考を登録しない。優先参考の登録に失敗した場合も「あとで読む」の追加は取り消さず、失敗を表示する。既存の「あとで読む」所属への再追加では優先参考を重複登録しない。新規登録時は記事の既読化・ブックマーク保存・所属追加を一体として確定し、途中失敗時はまとめて取り消す。あとで読むの解除・復元は新しい学習参考の登録操作とは扱わない。RSS未読ウィジェットから「あとで読む」に追加した場合も、RSSの優先参考として同じ学習へ登録する。ウィジェット側の学習登録が失敗しても「あとで読む」の保存は維持する。
- 手動入力した除外条件、学習された除外条件、学習された優先条件を別々に保存する。AIは手動条件を書き換えない。優先参考の単独登録操作は設けず、RSS記事を「あとで読む」に追加する操作で登録する。優先・除外参考には正負のラベルを付け、どちらかが追加されると最後の追加から約30秒後に両方の学習条件を同時に見直す。優先参考が既存の除外条件と重なる場合は除外側の一般化も修正し、逆方向も同様に調整する。学習済み参考は削除せず、過去の正負の参考を有界に再利用する。画面を閉じても処理を継続し、失敗時には両条件と未処理feedbackを保持する。

- 「除外参考」で保存したfeedbackはRSS所有のdurable stateとして保持し、学習成功またはユーザーによる取消しまで消費しない。
- 新しいfeedbackが追加されるたびに学習開始のdebounceを更新し、最後の追加から約30秒後に学習を開始する。推論失敗または構造化結果を適用できない場合は、既存の学習条件と未処理feedbackを保持して再試行可能にする。
- 学習開始後にmanual conditionのrevisionまたは実行先providerが変わった場合は、その学習結果を適用せず、今回利用したfeedbackも消費しない。
- 学習成功時は、その学習開始時に取得したfeedbackだけを消費する。学習中に追加されたfeedbackは未処理のまま残し、次の学習対象にする。
<!-- /formal-requirement -->
- 学習AIの構造化結果は除外・優先の学習条件を一括して返し、いずれかを更新したか、両方とも変更不要かを明示する。更新結果なのに両条件が変わらない、変更不要なのにいずれかが変わるなど結果と条件が矛盾する場合は学習失敗として扱い、feedbackを消費しない。
- RSS設定では未処理の優先参考・除外参考の件数を常に表示し、学習された両条件を別々にリセットでき、リセット時は対応する種類の学習済み参考履歴も削除する（未処理参考は維持する）。未処理が残っている場合は学習待ちまたは再試行対象であり、0件になったうえで学習条件が変わらない場合は既存条件でカバー済みとして処理されている。
- 推薦評価は判定に利用した条件revisionとともに保存する。実行先を変更した場合もrevisionを進め、現在未読の記事を新しい実行先で再評価する。RSS更新で取得した未読記事のうち現在revisionで未評価・古い評価・直前の推論失敗に該当する記事は、記事単位のバックグラウンドキューへ追加して順次評価する。条件が変わった場合も現在未読の記事を同じキューへ再投入する。評価処理は画面を閉じても継続し、端末内AI選択時は各記事の間で他の端末内AIタスクへ実行機会を渡す。クラウドAI選択時はネットワーク接続を必要とし、クラウドAIの一時停止設定に従う。
- 統合ビューの未読RSS記事にも同じ推薦評価を表示し、RSS未読一覧と同じ通常左 / 深い左の操作距離と切替フィードバックで「既読」と「除外参考」を利用できる。統合ビュー独自の推薦状態や学習処理は持たず、RSSが所有する評価状態と操作を投影する。

### 形式モデル

- [Quint: `rss_feedback_learning.qnt`](../../spec-models/quint/rss_feedback_learning.qnt) — feedbackのdebounce、失敗保持、stale policy resultの拒否、学習中に追加されたfeedbackの次回持越しを検査する。

## 4.2 ブックマークとあとで読む

- コンテンツをブックマークとして保存できる。
- タグとフォルダで整理できる。
- ブックマーク一覧は既定でブックマーク日時の新しい順に表示し、ブックマーク日時 / 記事公開日時と新しい順 / 古い順を切り替えられる。選択した日時基準は一覧の日付見出しと各項目の日時表示にも利用する。
- 「あとで読む」は Curation Context が所有する system folder として扱う。
- RSS の「あとで読む」一覧の日付見出しと各項目の日時表示にはブックマーク日時を利用する。
- RSS の「あとで読む」では、現在の並び順を基準にレビューを開始し、開始時点の対象を1件ずつ連続して確認できる。レビュー中に新しく追加された記事はそのセッションへ差し込まない。
- レビューでは記事タイトル、配信元、保存済み要約の全文を表示する。要約が未生成の場合は Summary が所有する既存の要約キューへ要求し、画面表示中は保存結果を反映する。要約待ちや失敗中でも記事の整理操作は継続できる。
- レビュー中は「記事を開く」「はてブを見る」を利用でき、戻ったときは同じレビュー対象と進捗へ復帰する。
- レビューの状態変更は固定ボタンの「保留」「未分類へ」「削除」で行い、「未分類へ」「削除」の後は自動的に次の記事へ進む。これらの変更は下部の固定操作領域と重ならない位置に短時間表示される Snackbar の「元に戻す」から復元でき、操作しなければ Snackbar は自動的に閉じる。
- レビューの進捗は画面内の一時状態とし、新しい durable state として保存しない。最後まで進むと完了画面で現在の「あとで読む」残件数を表示する。
- 共有インテントやインポートからブックマークを追加できる。
- 共有インテントから追加する場合、共有元がコンテンツタイトルを提供していればそれを記事タイトルとして優先し、提供されない場合は共有件名、共有テキスト内のタイトルを利用する。これらからタイトルを得られない場合は共有URLの静的HTMLからページタイトルを取得し、取得できない場合だけURLのhost名へfallbackする。
- 保存済みコンテンツへAI要約・タグ等の補完処理を行える。
- 自動AI処理対象の保存済みブックマークについて、要約とタグ付けを一括再実行できる。
- 一括再実行でメタデータ生成まで成功した記事は、既存タグを新しく生成されたタグで置き換える。処理中の記事は重複してキューへ追加しない。
- 単記事の要約再生成では「ブックマークのタグも再生成」を選択でき、既定はOFFとする。ONの場合だけ、メタデータ生成成功後に既存タグを生成タグで置き換える。

## 4.3 Reddit / 動画購読source

- Reddit は source 固有の購読・表示・判定を自身のContextで扱う。
- 動画チャンネル購読は Video Context が購読型Providerとして扱い、provider設定、subscription、更新、未読状態を共通のVideo lifecycleで管理する。
- 動画Providerは組み込みProviderに加えて、ユーザーが任意のJavaScript functionを設定するcustom Providerを複数追加できる。custom Providerでもsubscription、未読、あとで見る、保存、再生状態は共通のVideo lifecycleを利用する。
- 初期の組み込み動画Providerでは通常動画だけを更新対象とし、短尺専用形式とライブ配信は更新対象外とする。
- 購読型動画の未読、あとで見る、履歴、保存、再生は動画機能内で完結させ、統合ビューへ投影しない。
- 端末の共有メニューから http/https URL を「動画へ追加」へ共有すると、Web動画として動画機能へ追加し、動画画面へ遷移する。
- 自動AI処理の対象可否は source / content type の方針に従う。

## 4.4 統合ビューと履歴

- 複数sourceのコンテンツを横断して閲覧するpresentationを提供する。
- 統合ビューの未読一覧でも、RSSの現行推薦スコアがある記事をスコア降順で優先し、同点とスコアのないRSS / 他sourceのアイテムは日時の新しい順 / 古い順で並べる。既定は新しい順とし、日時の昇降順切り替えは未読一覧に適用する。「あとで読む」「履歴」の並び順は従来どおりとする。
- 統合ビュー上部の source フィルターには通常feed、Reddit、メールの未読件数を表示し、一覧領域を優先するため重複する全体件数サマリーは表示しない。
- 購読型動画は統合ビューの「未読 / あとで読む / 履歴」と source フィルターには表示しない。
- 統合ビュー下部の「未読 / あとで読む / 履歴」タブは、app shell が確保済みの system navigation 領域を重複して確保しない。
- 履歴や保存状態は owner Context の API を通して参照する。

## 4.5 要約の音声再生

<!-- formal-requirement

-->
- RSS の「あとで読む」から、現在表示している並び順の記事を「音声で聴く」で連続再生できる。
- 各項目は記事タイトルと保存済み要約を端末の音声合成機能で読み上げる。
- 保存済み要約がない記事は Summary が所有する既存の要約キューへ要求し、利用可能になった要約を読み上げ対象にする。Audio独自の要約生成は行わない。
- 要約を取得できない項目は再生対象から除外し、取得できた項目の順序は元の「あとで読む」の並び順を維持する。
- 音声ファイルは再生順に生成し、最初の再生可能な1件の音声が完成した時点で再生を開始する。全件の音声生成完了は待たず、再生中も後続記事の音声生成を継続して再生queueへ順次追加する。
- 再生が後続音声の生成に追いついた場合は、次の音声が完成してqueueへ追加された時点で連続再生を再開する。
- 再生、一時停止、前の記事、次の記事、15秒戻し、30秒送り、1x / 1.25x / 1.5x / 2x の再生速度変更を提供する。
- 画面を閉じてもmedia playbackとして再生を継続し、通知、lock screen、Bluetooth等の標準media controlから操作できる。
<!-- /formal-requirement -->

- 再生開始、再生完了、skip、停止、queue完了のいずれもContentの既読 / 未読状態、CurationのRead Later membership、Bookmark stateを変更しない。
- Audioのqueue、再生位置、再生済み状態、生成音声はdurable user stateとして保存しない。生成音声は再生成可能なcacheとして扱い、backup / export対象にしない。

## 4.6 ニュースポッドキャスト

- トップレベルの「ニュースポッドキャスト」画面で、Podcast専用のRSS / Atom sourceを表示名とfeed URLで追加し、複数sourceを1つの番組として登録・編集・削除できる。同じsourceは複数番組から再利用でき、番組で未使用のsourceは削除できる。
- Podcast sourceはRSS readerの購読とは別に管理する。Podcast sourceを追加してもRSS購読へ自動追加せず、RSS購読の追加・削除・既読化もPodcast sourceへ反映しない。
- 番組ごとに利用するPodcast source、生成AI、1回に使う最大ニュース数、毎日の自動生成時刻、聞かなくてよいニュースの除外条件を設定できる。除外条件は自然文で入力し、空欄なら内容による除外を行わない。生成AIはローカルAIまたはクラウドAIを明示選択し、自動fallbackは行わない。
- 手動または設定した定刻に、選択したPodcast sourceのfeedを取得し、その番組でまだ生成済みでも除外済みでもないentryから音声番組用の日本語原稿を生成する。RSS reader上の未読 / 既読状態は候補判定に利用しない。画面から開始した生成もdurableなbackground workとして実行し、画面を離れたり端末をロックしたりしてもUIのlifecycleに依存せず継続する。
- 除外条件が設定されている場合は、番組で選択した生成AIを使ってfeed内のタイトル、情報源、本文から各候補を判定し、条件に明確に該当する記事を同一ニュースのクラスタリング前に除外する。ローカルAIを選択した場合は端末内で判定し、クラウドAIを選択した場合は除外条件とこれらの判定材料を同じクラウド推論先へ送る。feed本文中の命令文は判定対象データとして扱い、AIへの指示として実行しない。
- 除外判定の推論または構造化出力の検証に失敗した場合は記事を欠落させず、その回は全候補を残して通常のクラスタリングへ進む。

- ニュース除外判定の最終結果は、今回の候補記事全体をincluded / excludedへ分割し、各候補をちょうど一方へ所属させる。候補の欠落、includedとexcludedの重複、同一候補の重複出現を許可しない。
- 除外判定の推論、tool call、decode、validationのいずれかが失敗した場合は、その回の部分的な除外結果を採用せず、全候補をincludedへ戻してexcludedを空にする。複数batchの途中で失敗した場合も、それ以前のbatchだけを確定しない。
- fallback時も候補集合を失わず、そのまま後続のクラスタリング対象へ渡す。

- 除外されたentryは番組単位で除外済みとして記録し、次回以降は再判定しない。除外条件を後から変更しても過去の除外済みentryは自動復活させない。

- 既存WebView Cookie、mail credential、SMB credential、cloud token等をcustom Providerへ暗黙に共有しない。認証付きProviderが必要な場合はfunction codeと分離したprotected credential capabilityとして別途設計する。
<!-- /formal-requirement -->
- custom Providerは画面を開いていないbackground refreshでも同じfunctionを実行できる。functionの失敗や不正な戻り値はそのsubscriptionの更新失敗として扱い、他Provider / subscriptionの更新を継続する。
- 有効なProviderへチャンネル等のsource URLまたはProvider固有の入力をsubscriptionとして追加し、手動またはbackgroundで更新できる。
- custom Providerのsubscriptionでは入力と併せて表示タイトルを任意指定でき、登録済みタイトルも編集できる。タイトルを省略した場合は取得したタイトルを初期値とし、以後のrefreshでは保存済みタイトルを保持する。タイトルとsource URLは購読設定に併記する。
- Provider更新で新しく発見した動画はVideo catalogへ追加し、provider由来の未読として表示する。既存動画の更新では未読 / 既読、あとで見る、保存、再生位置を保持する。
- provider由来の未読 / 既読状態と視聴済み状態は独立して扱う。既読化で視聴済みへ変更せず、再生完了で自動的に既読化しない。
- 購読型Provider由来の未読、あとで見る、履歴、保存、再生は動画機能内で確認・操作し、統合ビューには重複表示しない。

- subscription解除時、未保存かつ再生履歴のない取得済み動画は削除できる。保存済みまたは再生履歴を持つ動画はsubscription membershipだけを外してcatalogへ残す。subscription membershipを失ったProvider動画は、保存済みまたは再生履歴のいずれかがある間だけcatalogへ保持し、両方なくなった時点でcatalogから削除する。
<!-- /formal-requirement -->
- 旧専用購読画面はトップレベル導線から廃止し、購読設定は「動画」画面へ集約する。既存インストールのsubscriptionと未読状態は更新時にVideo-owned stateへ移行する。
- SMB接続の表示名、host、port、username、domain、passwordはアプリの全体設定から接続プロファイルとして登録・編集する。passwordは画面へ再表示しない。
- 動画設定では全体設定のSMB接続プロファイルを選び、動画として同期するshareとパスを個別に登録する。蔵書とは異なるshare / pathを指定でき、同じ接続プロファイルへ複数の動画同期場所を登録できる。
- 全体設定で削除された接続先を参照する動画同期場所は設定画面で無効として表示し、削除できる。無効な同期場所はSMB同期対象から除外し、他の有効な同期場所の同期を妨げない。
- SMB passwordやserver credentialをVideo側へ複製しない。SMB credentialはLibrary側が所有する保護領域を利用し、Video側は接続プロファイルIDと自身のshare/pathだけを保持する。
- SMB同期で登録した動画は、一覧に表示された時点で動画ファイルから代表フレームをサムネイルとして生成する。生成結果は再生成可能な端末内cacheとして扱い、生成失敗時も同期・再生は継続する。
- Media3で通常のHTTP動画とHLS streamを再生する。SMB動画は動画ファイル全体を事前downloadせずrandom-access readで再生する。
- 再生準備中 / 読み込み中 / 長時間読み込み / 再生エラーを画面上で区別して表示する。10秒以上の待機では経過時間を示し、30秒以上続く場合は再生エラーがまだ検出されていないことを明示して再試行できる。Media3が再生エラーを返した場合は再生不能としてエラーコードと再試行操作を表示する。
- 再生画面では全画面表示へ切り替えられる。全画面へ入ると横向き表示へ切り替えてsystem barsを隠し、画面端のスワイプで一時表示できる。全画面解除または再生画面を閉じると通常の縦向き表示へ戻る。
- 再生画面を開いている間は画面の自動消灯を抑止する。プレイヤー左半分をダブルタップすると15秒戻し、右半分をダブルタップすると15秒送りを行う。ダブルタップ時は再生コントローラや操作オーバーレイを表示せず、単タップ時だけ再生コントローラを表示 / 非表示する。
- 動画ごとに再生位置、duration、最終再生日時、視聴済み状態を保存し、次回再生時に保存位置から再開する。既存版で保存済みのSMB動画は、同じserver/pathの対応が一意に決まる場合、shareを含む新しい動画identityへ初回再同期時に再生状態を引き継ぐ。
- durationが取得できる動画は95%以上再生すると視聴済みとし、一覧から手動で視聴済み / 未視聴を変更できる。
- 初期実装の動画再生はforeground画面内で行う。画面を閉じた後のbackground音声継続、Cast、動画download、transcodingは提供しない。
