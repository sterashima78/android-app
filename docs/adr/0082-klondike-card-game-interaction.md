# ADR-0082: クロンダイクはルールを domain に置きタップ選択で操作する

- Status: Accepted
- Date: 2026-08-16

## Context

ADR-0080 で一人用ゲームを `:feature:game:{domain,ui}` に分離し、ゲーム固有ルールを Compose から独立させる方針を採用した。2本目のゲームとしてクロンダイクを追加する。

クロンダイクではカード列の移動、場札・組札・山札の状態遷移がゲーム規則そのものであり、UI に判定を置くとテストが難しくなる。また Android の縦長・狭幅画面でドラッグ操作だけに依存すると、7列の場札で正確なドロップ領域を確保しづらく、アクセシビリティ上も操作手段が限定される。

将来スパイダーソリティアを追加する可能性があるが、現時点でクロンダイクとスパイダーの共通エンジンを先に設計すると、異なる配札・完成条件・移動可能列・山札規則まで抽象化することになり、必要性が確認されていない抽象を増やす。

## Decision

- カード、場札、山札、捨て札、組札、選択状態、および合法手判定は `:feature:game:domain` が所有する。
- Compose UI は状態の表示とユーザー操作の通知に限定し、合法手の判断を持たない。
- モバイルでの基本操作は「カードをタップして選択し、移動先をタップする」方式とする。ドラッグ操作は必須としない。
- 山札は1枚めくりとし、山札が空になった場合は捨て札を回数制限なしで再利用できるルールを採用する。
- 場札からカードを移動して伏せ札が最上段に露出した場合は自動的に表向きにする。
- ゲーム進行状態は `KlondikeViewModel` のメモリ上に保持し、永続化は行わない。これは数独と同じ初期方針とする。
- `PlayingCard` など明確に汎用な値表現は Game domain 内に置くが、クロンダイクと将来のスパイダーを統合する汎用カードゲームエンジンは現時点では作らない。2つ目のカードゲーム実装時に実際の共通部分を抽出する。

## Consequences

### Positive

- クロンダイクの合法手を JVM unit test で検証できる。
- 7列の狭い盤面でもタップ中心で操作でき、ドラッグ精度に依存しない。
- UI を変更してもゲーム規則を再利用できる。
- スパイダー追加時に実装実績から共通化範囲を決められる。

### Negative

- ドラッグ中心の一般的なソリティア UI と比べ、初版の操作感は簡素である。
- 3枚めくり、山札再利用回数制限、途中保存などのバリエーションは初版では扱わない。
- スパイダー追加時には共通カード表現や盤面操作の再整理が発生する可能性がある。

## Relationship

ADR-0080 の Game feature の責務分離を継承する。将来スパイダーソリティアを追加する際は本 ADR を再確認し、共通化が実データに基づいて妥当になった時点で追記または新 ADR を作成する。
