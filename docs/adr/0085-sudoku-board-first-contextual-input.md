# ADR-0085: 数独は盤面優先の固定ビューポートとコンテキスト入力を採用する

- Status: Accepted
- Date: 2026-08-17
- Refines: ADR-0080

## Context

ADR-0080 で追加した数独の初期 UI は、9 個の数字ボタンを 3×3 で常時表示し、画面全体を縦スクロール可能にしていた。この構成ではスマートフォン縦画面で入力ボタンが大きな面積を占有し、数独で最も重要な 9×9 盤面の表示領域が相対的に小さくなる。また、ゲーム中に縦スクロールが発生すると盤面と入力操作の位置関係が安定しない。

一方、数字入力は編集可能なセルを選択している間だけ必要であり、固定数字の確認中や問題開始直後には常設する必要がない。

## Decision

- 数独のプレイ画面では縦スクロールを使用しない。
- ヘッダーと入力領域を最小限にし、残りの領域から幅と高さの小さい方を使って正方形の盤面を最大化する。
- 数字入力 UI は常設せず、編集可能なセルをタップしたときだけ表示する。
- 入力 UI は 1〜5 / 6〜9 + 消去の 2 段構成とし、スマートフォンでも各ボタンのタップ領域を確保しつつ、従来の 3×3 常設キーパッドより高さを抑える。
- 問題開始時はセル未選択とし、入力 UI を表示しない。正しい数字を入力した後は選択を解除して入力 UI を閉じる。誤入力時はセル選択を維持し、続けて再入力できるようにする。
- 選択セル、同じ行・列・3×3 ブロック、選択済み数字と同じ値を段階的にハイライトする。色の切り替えと入力 UI の出入りには短い Compose animation を使うが、ゲームルール側へ視覚状態を持ち込まない。
- 選択セルと同じ行・列・3×3 ブロックですでに使われている数字は入力ボタンを無効化する。これは UI 上の補助であり、正誤判定の最終責務は引き続き `:feature:game:domain` が持つ。
- 完成表示は盤面下へコンテンツを追加してレイアウトを押し下げるのではなく、プレイ画面上のオーバーレイとして表示する。

## Consequences

### Positive

- 縦画面の大半を盤面へ割り当てられ、盤面を見ながら考えやすくなる。
- 入力 UI が必要なときだけ現れるため、通常時の視覚的なノイズが減る。
- 盤面サイズが利用可能領域から決まるため、小さい画面でもスクロールせず収まる。
- 基本的な数独制約に反する数字を事前に無効化でき、誤タップを減らせる。
- UI のリッチさをアニメーションと状態ハイライトで実現し、画像・音声などの追加アセットを必要としない。

### Negative

- 数字ごとに編集セルを選択するため、常設キーパッドよりタップ回数が増える。
- 高さが非常に小さい画面では、入力領域を確保する分だけ盤面が縮小する。
- 正解入力後に選択が解除されるため、同じセルを消去する場合は再度タップする必要がある。

## Relationship

ADR-0080 の Game feature / domain / UI の責務分離と問題生成方式は変更しない。本 ADR は数独のプレイ画面と選択状態の操作ライフサイクルのみを具体化する。
