# ADR-0290: RSSフィード別通信診断を既存集計へ拡張する

- Status: Accepted
- Date: 2026-10-22
- Refines: [ADR-0289](0289-on-device-network-usage-diagnostics.md)

## Context

機能別通信量だけでは、フィードの取得サイズ、更新頻度、条件付き取得の効果、取得契機を切り分けられない。フィード名やURLを診断用ストレージへ重複保存するとプライバシー上の取り扱いが増える。

## Decision

- 既存の共有HTTP転送量計測を拡張し、通常の登録済みRSS/Atomフィードリクエストに限りフィードID、更新契機、最終HTTPステータスを添付する。
- Android compositionが従来の90日以内・回線別の日次集計を拡張する。フィードID、更新契機、受信byte、取得試行回数、HTTP 304回数だけを保存し、URL、ホスト、タイトル、個別の通信時刻は保存しない。
- 画面表示時のみ既存のRSS Domain repositoryから現在のフィード表示名を解決する。削除済みのフィードは匿名の代替ラベルで表示する。
- 診断画面では選択期間・回線に従う受信量上位10件と、各フィードの取得回数、304応答の比率、取得契機内訳を表示する。
- 新しいDB schema、外部通信、権限、Worker、ユーザーデータのsource of truth、backup対象は追加しない。フィード更新のスケジュールや重複実行ポリシーも変更しない。
- WebViewで実行するスクレイピングの転送は共有HTTPクライアント経由ではないため、フィード単位のバイト計測対象外であると明記する。

## Consequences

通信量はHTTPレスポンス本文の読み取りバイト数であり、通信レイヤーの実測値や送信量、リダイレクトごとの明細は表さない。304の比率の分母は通常RSSフィードの取得リクエスト数（通信失敗も含む）。取得契機は開始元が明示する区分であり、画面生成時の全件更新と周期更新が重複することを検出できる。既存の集計は維持され、古い版へ戻してもアプリ本体のデータへ影響しない。

## Verification

- 304など本文ゼロのレスポンスもリクエストとして計数することを検証する。
- 更新起点が複数の並列リクエストに伝播することを検証する。
- 集計期間・回線・上位10件と匿名表示名の扱いを検証する。
