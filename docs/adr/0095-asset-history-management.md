# ADR-0095: 資産履歴は日次スナップショット明細として保存しカテゴリ設定を履歴から分離する

- Status: Accepted
- Date: 2026-08-18
- Updated: 2026-08-18

## Context

MoneyForward ME などから取得した資産を時系列で追跡し、既存 TSV データも統合して閲覧したい。同じ日・同じ資産名が複数口座や複数明細として現れるため、資産名だけを一意キーにすると金額を失う。またカテゴリ分類は運用中に変更したく、過去行にカテゴリ文字列を焼き付けると再分類が難しい。

資産情報は個人のセンシティブな情報であり、この public repository に実データを fixture やログとして置いてはならない。また、資産履歴はアプリ内で永続的に管理するユーザーデータなので、既存のファイル / Google Drive バックアップから欠落させない必要がある。

## Decision

`feature:asset:{domain,data,ui}` を追加する。

### スナップショット

`asset_entries` は日付、資産名、金額、口座名、取得 source を明細単位で保存する。同日同名の複数行を許容し、表示時に合算する。

ファイルインポートは TSV のみを受け付ける。1列目を日付、2列目を資産名、3列目を金額、4列目を金融機関・口座名として扱う。4列目は空でもよく、5列目以降は資産情報として取り込まない。金額はカンマ、半角・全角の円記号、`円`、空白を除去して整数として解釈する。

TSV では2列目と4列目の組み合わせを資産の識別名とする。4列目が非空なら `2列目 / 4列目` を `asset_entries.name` に保存し、4列目の値自体も `account` に保持する。4列目が空なら2列目だけを `name` に保存する。MoneyForward 取得でも資産名と保有金融機関に同じ識別名生成規則を適用し、TSV の過去履歴と同一項目として扱えるようにする。

同じ日付を再インポートまたは WebView から再取得した場合、その日付のスナップショットをトランザクション内で置換する。これにより再取得による二重計上を防ぐ。

### カテゴリ

`asset_categories` は「資産名 -> 現在のカテゴリ」だけを保存する。履歴行にはカテゴリを保存しない。カテゴリを変更すると過去履歴も新しいカテゴリで再集計される。未設定は「その他」とする。

MoneyForward collector は分類ロジックを持たず、ページから資産名・評価額/残高・保有金融機関だけを取得する。分類は資産画面の設定タブで行う。

### 可視化

最新スナップショットについて資産総額とカテゴリ別内訳を表示する。カテゴリ別内訳には金額に加えて資産総額に対する割合を併記する。総額が0の場合は割合を算出不能として表示する。

履歴は、集計モデルが保持する日付ごとのカテゴリ別金額をカテゴリごとの積み上げエリアグラフとして表示する。表示モードは「金額」と「100%構成比」を画面上で切り替えられるようにする。金額表示は0を基準として正の値と負の値をそれぞれ積み上げる。100%構成比表示は、各日付の正のカテゴリ合計を100%、負のカテゴリが存在する場合はその絶対値合計を別の100%として正負それぞれを正規化する。負のカテゴリが存在しなければ通常の0〜100%積み上げグラフになる。

カテゴリの描画順はカテゴリ名で安定させ、同じ履歴データの再描画でエリアの対応関係が入れ替わらないようにする。カテゴリ色は識別しやすい拡張パレットから同じ安定順で割り当て、少なくとも24カテゴリまでは色を重複させない。グラフ直下に最新のカテゴリ別内訳を配置し、各行にグラフと同じ色のマーカーを表示する。内訳を凡例として兼用するため、グラフ内に重複するカテゴリ凡例は置かない。

### ナビゲーションと画面構成

資産管理は設定の一項目ではなく、継続的に参照する独立機能としてサイドバーナビゲーションの `資産` から開く。設定画面から資産管理への導線は削除する。

資産画面は `概要`、`インポート`、`設定` の3タブに分ける。`概要` は資産総額・推移・カテゴリ別内訳の閲覧、`インポート` は TSV と MoneyForward ME からの取得、`設定` は資産項目ごとのカテゴリ設定を担当する。ルートのサイドバー選択状態は asset feature 内のタブ選択とは分離する。

app 層の route が `AssetViewModel` を生成し、`feature:asset:ui` は画面とタブ内UIを担当する。これにより application container への依存を feature UI へ持ち込まない。

### MoneyForward DOM

collector は CSS 階層や nth-child を主要契約にせず、資産ページ内の table header から列を認識する。「種類・名称」「銘柄名」「名称」を資産名、「残高」「評価額」「現在価値」を金額、「保有金融機関」を口座として扱う。サイト変更でこれらの見出しが変わった場合は collector を更新する。

### バックアップ

バックアップ形式を v6 に更新し、`asset_entries` と `asset_categories` をそれぞれ `assetEntries` / `assetCategories` として保存・復元する。v1〜v5 の既存バックアップは引き続き復元可能とし、資産データは存在しないものとして扱う。

TSV インポート、MoneyForward 取得、カテゴリ変更が成功したときは既存の `BackupChangeScheduler` を呼び、Google Drive 自動バックアップの変更検知対象に含める。

## Public repository safety

- 実際の資産名、口座名、金額、Cookie、セッション情報を test fixture、ログ、ADR、PR 説明に含めない。
- collector の結果 JSON をログ出力しない。
- MoneyForward の認証情報を Repository へ渡さない。
- テストでは人工的な名称と金額だけを使用する。

## Consequences

- TSV の2列目が同じでも4列目の金融機関・口座名が異なれば別の資産項目として扱える。
- 4列目が空の既存行も2列目だけで継続して扱える。
- 円記号やカンマ付きの金額を TSV から取り込める。
- TSV と MoneyForward で同じ資産名・金融機関の組み合わせを同じ識別名として扱える。
- 同一銘柄を複数口座で保有していても正しく合算できる。
- カテゴリ変更を過去データへ即時反映できる。
- TSV と WebView 取得を同じ履歴モデルへ統合できる。
- 資産履歴とカテゴリ設定を既存バックアップと一緒に保全できる。
- サイドバーから資産状況へ直接アクセスでき、閲覧と管理操作をタブで分離できる。
- 最新時点ではカテゴリごとの金額と構成比を同時に確認できる。
- 履歴では総額の増減だけでなく、カテゴリごとの金額変化と構成比変化を切り替えて確認できる。
- 負の金額を含む履歴でもエリアが正の積み上げへ混入せず、100%表示では正負それぞれの構成を比較できる。
- グラフと内訳で同じ色対応を使うため、カテゴリ数が増えても対応関係を追いやすい。
- 同日中の部分的なスナップショットを複数 source から混在させる用途には向かない。現時点では各入力をその日の完全スナップショットとして扱う。

## Relationship to existing ADRs

- ADR-0003 / 0004 の module ownership と layer ルールに従う。
- ADR-0094 の安全な Web collector capability を MoneyForward 取得に使用する。
- 既存バックアップの後方互換性を維持しつつ、資産データを v6 で追加する。
- ADR-0055 に従い新規番号 0095 を使用する。
