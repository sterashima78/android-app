# ADR-0008: メール一覧を未読キュー中心のトリアージ UI として扱う

- Status: Accepted
- Date: 2026-08-09
- Updated: 2026-08-09

## Context

Yomitori の RSS は、未読一覧を処理キューとして扱い、スワイプで既読・ブックマーク・あとで読むへ状態を移しながら未読を減らしていく操作モデルを採用している。

Gmail 機能は複数アカウントの統合表示、検索、既読、スター、アーカイブ、ラベル等の操作を備えているが、一覧は受信・未読・スター・すべての Mailbox を横並びにした一般的なメールクライアント型で、RSS と操作モデルが異なっていた。

アプリ全体では「あとで処理する対象を一覧から順に減らす」操作を一貫させたい。

また、Yomitori のアーカイブ一覧は過去の Gmail 全履歴を閲覧する用途ではない。Gmail 側ですでにアーカイブされている大量のスレッドを初回同期してローカルへ保持すると、アカウント追加時の同期時間、通信量、保存量が増える。Yomitori で処理したメールの履歴だけ残せればよい。

## Decision

メール一覧の主表示を「未読」「スター」「アーカイブ」の 3 状態に絞り、未読を既定表示とする。

### 1. 未読は受信トレイ内の未読を処理キューとして扱う

メールの未読一覧は、Gmail 上で `UNREAD` かつ `INBOX` にあるスレッドを表示対象とする。

したがって未読一覧からアーカイブしたメールは、未読フラグ自体を変更しなくても現在の処理キューから外れる。

既読操作でも現在の処理キューから外れる。

スター自体は既読・受信トレイ状態とは独立した Gmail の状態として維持する。ただし未読一覧で新しくスターを付ける操作は RSS の「保存して処理済みにする」操作に合わせ、`STARRED` を付与した後に `UNREAD` を外す。これによりスター付きメールへ振り分けながら未読キューを減らせる。

すでにスター済みの未読メールからスターを外す操作は、スター状態だけを変更し、未読状態は維持する。

### 2. Gmail 側の既存アーカイブは同期せず、アプリでアーカイブしたメールだけを保持する

Gmail の Archive は独立した system label ではなく `INBOX` label を外す操作である。しかし Yomitori では「Gmail 上で受信トレイ外にあるすべてのメール」をアーカイブ一覧とはみなさない。

初回同期は Gmail 検索 `in:inbox` を指定し、受信トレイ内のスレッドだけを取得する。Gmail 側ですでにアーカイブ済みのスレッドは初回同期対象にしない。

Yomitori からアーカイブ操作を行ったスレッドは、Gmail では従来どおり `INBOX` label を外す。同時にローカル `mail_threads.archived_locally` を 1 にし、このフラグを Yomitori のアーカイブ表示の所有状態とする。

アーカイブ一覧は次の条件を満たすローカルスレッドだけを表示する。

- `in_inbox = 0`
- `archived_locally = 1`

Gmail History API の差分同期で受信トレイ外のスレッドを検出した場合、`archived_locally = 1` のスレッドだけを継続してキャッシュする。Yomitori でアーカイブしていないスレッドが Gmail 側で受信トレイから外れた場合は、ローカルキャッシュから削除する。

アーカイブ一覧から「受信トレイ」へ戻す操作では `INBOX` label を再付与し、`archived_locally` を 0 に戻す。

既存 DB を version 7 へ移行する際、既存スレッドの `archived_locally` は 0 とする。このため以前の実装で Gmail 側から同期済みだったアーカイブメールは新しいアーカイブ一覧には表示されない。

検索で Gmail の `in:archive` を利用する場合も、検索結果として採用・保存するのは `archived_locally = 1` の既存ローカルスレッドに限定する。

参考:

- https://support.google.com/mail/answer/6576
- https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.threads/list

### 3. RSS と同じ距離ベースのスワイプ操作を採用する

未読一覧では次の操作を提供する。

- 左スワイプ: 既読
- 右スワイプ: スター / スター解除
- 右へ深くスワイプ: アーカイブ

未読メールへ新しくスターを付けた場合は同時に既読化し、未読一覧から外す。

スター一覧ではスター解除を主操作とし、アーカイブもスワイプで実行できる。

アーカイブ一覧では受信トレイへ戻す操作とスター切替をスワイプで実行できる。

スワイプ距離とカード退場アニメーションは RSS の ArticleList と同じ考え方を使う。ただし mail feature は article feature に依存させず、mail UI 内で同等の gesture semantics を実装する。

### 4. Gmail の状態とローカル所有状態を分ける

Gmail 上のメール状態は既存ラベル操作を利用する。

- 既読: `UNREAD` label を外す
- スター: `STARRED` label を付け外しする
- 未読一覧からスターへ振り分け: `STARRED` を付けた後に `UNREAD` を外す
- アーカイブ: `INBOX` label を外す
- 受信トレイへ戻す: `INBOX` label を付ける

同期済みの MailThread が持つ `isInInbox` / `isUnread` / `isStarred` は Gmail 側の状態を表す。

一方、`archived_locally` は Gmail のラベルではなく「このスレッドを Yomitori のアーカイブ履歴として保持するか」というローカル所有状態を表す。Gmail 側の既存アーカイブを同期対象から外すため、この状態は Gmail の `INBOX` 有無から推測せず明示的に保存する。

### 5. 一覧から外れる操作は楽観的に UI へ反映し、失敗時に復元する

既読、未読一覧からのスター付与、アーカイブ、スター解除、受信トレイ復帰など、現在の一覧から対象が外れる操作はカードを先に一覧から除外する。

Gmail API 操作が失敗した場合はキャッシュを再読込し、カードを現在の実状態に戻してエラーを表示する。通信エラー時にスワイプ済みカードが画面外へ残り続ける状態を作らない。

また、未読・アーカイブの絞り込みは `LIMIT 100` を適用する前の repository query で行い、UI 側の事後フィルタだけに依存しない。

## Consequences

### Positive

- RSS とメールで「未読を順に減らす」操作モデルが揃う
- スターへ振り分けたメールも未読キューから外れ、処理済みとして扱える
- メール一覧で頻繁に使う状態変更を詳細画面を開かずに実行できる
- Gmail 側の過去のアーカイブを初回同期しないため、アカウント追加時の通信量と同期時間を抑えられる
- アーカイブ一覧には Yomitori でアーカイブしたメールだけが残る
- Gmail 側で別クライアントからアーカイブされたメールが Yomitori のアーカイブ一覧へ流入しない
- API 操作失敗時にスワイプ表示と Gmail の実状態が乖離しにくい

### Negative

- 未読一覧での「スター」は純粋なスター切替ではなく、スター付与時だけ既読化を伴うトリアージ操作になる
- `archived_locally` という Yomitori 固有の永続状態を追加する必要がある
- 既存 DB 移行時には以前 Yomitori でアーカイブしたメールと Gmail 側から同期したアーカイブを判別できないため、既存行はすべて非ローカルアーカイブとして扱う
- Yomitori は Gmail の完全なオフラインメールアーカイブにはならない
- RSS と mail のスワイプ実装は feature 間依存を避けるため現時点では共通コンポーネント化しない

## Relationship to existing ADRs

- ADR-0001 の UI / Domain / Data の責務分離を維持する
- ADR-0003 / ADR-0004 に従い、UI 共通化だけを理由に mail から article feature へ依存しない
- ADR-0006 の background sync / checkpoint / generation の仕組みは維持するが、full sync の対象を Gmail 全スレッドから受信トレイ内スレッドへ限定し、ローカルアーカイブは generation cleanup から除外する
