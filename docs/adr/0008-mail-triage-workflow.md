# ADR-0008: メール一覧を未読キュー中心のトリアージ UI として扱う

- Status: Accepted
- Date: 2026-08-09
- Updated: 2026-08-12

## Context

Yomitori の RSS は、未読一覧を処理キューとして扱い、スワイプで既読・ブックマーク・あとで読むへ状態を移しながら未読を減らしていく操作モデルを採用している。

Gmail 機能は複数アカウントの統合表示、検索、既読、スター、アーカイブ、ラベル等の操作を備えているが、一覧は受信・未読・スター・すべての Mailbox を横並びにした一般的なメールクライアント型で、RSS と操作モデルが異なっていた。

アプリ全体では「あとで処理する対象を一覧から順に減らす」操作を一貫させたい。Gmail のスターは Gmail 自身の状態であり、Yomitori の「あとで読む」と同一視すると、別のメールクライアントで付けたスターまで Yomitori の保留キューへ混在する。また、Yomitori の都合でスターを付けると Gmail 側の状態を不要に変更する。

また、Yomitori のアーカイブ一覧は過去の Gmail 全履歴を閲覧する用途ではない。Gmail 側ですでにアーカイブされている大量のスレッドを初回同期してローカルへ保持すると、アカウント追加時の同期時間、通信量、保存量が増える。Yomitori で処理したメールの履歴だけ残せればよい。

## Decision

メール一覧の主表示を「未読」「あとで読む」「スター」「アーカイブ」の 4 状態とし、未読を既定表示とする。

### 1. 未読は受信トレイ内の未読を処理キューとして扱う

メールの未読一覧は、Gmail 上で `UNREAD` かつ `INBOX` にあるスレッドを表示対象とする。

したがって未読一覧からアーカイブしたメールは、未読フラグ自体を変更しなくても現在の処理キューから外れる。既読操作でも現在の処理キューから外れる。

スター自体は既読・受信トレイ状態とは独立した Gmail の状態として維持する。未読一覧で新しくスターを付ける直接操作は従来どおり `STARRED` を付与した後に `UNREAD` を外し、スター付きメールへ振り分けながら未読キューを減らす。

「あとで読む」はスターとは別の Yomitori 独自状態とする。未読一覧から「あとで読む」に振り分ける場合は、ローカルのあとで読む状態を設定したうえで Gmail の `UNREAD` を外す。これにより未読キューからは処理済みとして外れつつ、Yomitori のあとで読む一覧へ残る。

### 2. 「あとで読む」は Yomitori のローカル状態として保存する

`mail_threads.read_later_locally` を追加し、アカウント ID と Gmail thread ID に紐づけて端末内 DB に保存する。

この状態は Gmail API の label へ変換しない。Gmail の `STARRED`、ユーザーラベル、`INBOX` の有無とは独立している。

- あとで読むへ追加: `read_later_locally = 1`
- あとで読むを解除: `read_later_locally = 0`
- 未読一覧から追加: ローカル状態を設定した後、Gmail の `UNREAD` を外す
- あとで読む一覧から解除: ローカル状態だけを解除する
- スター切替、アーカイブ、受信トレイ復帰: あとで読む状態を暗黙には解除しない
- ゴミ箱移動または Gmail 上で削除されたスレッド: ローカルキャッシュ削除とともにあとで読む状態も削除する

DB version 11 への migration では既存スレッドの `read_later_locally` を 0 とする。既存の Gmail スターからあとで読む状態を推測して移行しない。

### 3. Gmail 側の既存アーカイブは同期せず、アプリで保持する必要があるメールだけを残す

Gmail の Archive は独立した system label ではなく `INBOX` label を外す操作である。しかし Yomitori では「Gmail 上で受信トレイ外にあるすべてのメール」をアーカイブ一覧とはみなさない。

初回同期は Gmail 検索 `in:inbox` を指定し、受信トレイ内のスレッドだけを取得する。Gmail 側ですでにアーカイブ済みのスレッドは初回同期対象にしない。

Yomitori からアーカイブ操作を行ったスレッドは、Gmail では従来どおり `INBOX` label を外す。同時にローカル `mail_threads.archived_locally` を 1 にし、このフラグを Yomitori のアーカイブ表示の所有状態とする。

アーカイブ一覧は次の条件を満たすローカルスレッドだけを表示する。

- `in_inbox = 0`
- `archived_locally = 1`

`read_later_locally = 1` のスレッドも Yomitori が保持すべきローカル状態を持つため、Gmail 側で受信トレイ外になってもキャッシュを維持する。ただし `archived_locally = 0` であれば Yomitori のアーカイブ一覧へは表示しない。

Gmail History API の差分同期で受信トレイ外のスレッドを検出した場合、`archived_locally = 1` または `read_later_locally = 1` のスレッドだけを継続してキャッシュする。どちらのローカル所有状態もないスレッドが Gmail 側で受信トレイから外れた場合は、ローカルキャッシュから削除する。

アーカイブ一覧から「受信トレイ」へ戻す操作では `INBOX` label を再付与し、`archived_locally` を 0 に戻す。あとで読む状態は維持する。

検索で Gmail の `in:archive` を利用する場合も、検索結果として採用・保存するのは Yomitori がローカルで保持している既存スレッドに限定する。

参考:

- https://support.google.com/mail/answer/6576
- https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.threads/list

### 4. RSS と同じ距離ベースのスワイプ操作を採用する

未読一覧では次の操作を提供する。

- 左スワイプ: 既読
- 右スワイプ: あとで読む
- 右へ深くスワイプ: アーカイブ

スターは一覧行と詳細画面のスター操作から引き続き変更できる。未読メールへ新しくスターを付けた場合は従来どおり同時に既読化し、未読一覧から外す。

あとで読む一覧では、左スワイプであとで読むを解除する。スター切替やアーカイブはあとで読む状態と独立して操作できる。

カードの退場アニメーションとスワイプ距離は ADR-0015 の `SwipeActionListItem` を利用する。

### 5. Gmail の状態とローカル所有状態を分ける

Gmail 上のメール状態は既存ラベル操作を利用する。

- 既読: `UNREAD` label を外す
- スター: `STARRED` label を付け外しする
- 未読一覧からスターへ振り分け: `STARRED` を付けた後に `UNREAD` を外す
- アーカイブ: `INBOX` label を外す
- 受信トレイへ戻す: `INBOX` label を付ける

同期済みの MailThread が持つ `isInInbox` / `isUnread` / `isStarred` は Gmail 側の状態を表す。

一方、次の状態は Yomitori が所有する。

- `archived_locally`: このスレッドを Yomitori のアーカイブ履歴として保持するか
- `read_later_locally`: このスレッドを Yomitori のあとで読むキューへ保持するか

Gmail 同期でスレッド本体を更新するときも、これらのローカル状態は Gmail の label から再計算せず、既存 DB 値を引き継ぐ。

### 6. 一覧から外れる操作は楽観的に UI へ反映し、失敗時に復元する

既読、未読一覧からのあとで読む追加、未読一覧からのスター付与、アーカイブ、スター解除、あとで読む解除、受信トレイ復帰など、現在の一覧から対象が外れる操作はカードを先に一覧から除外する。

Gmail API 操作やローカル DB 更新が失敗した場合はキャッシュを再読込し、カードを現在の実状態に戻してエラーを表示する。通信エラー時にスワイプ済みカードが画面外へ残り続ける状態を作らない。

未読・あとで読む・アーカイブの絞り込みは `LIMIT 100` を適用する前の repository query で行い、UI 側の事後フィルタだけに依存しない。あとで読む一覧内の検索は Gmail に存在しないローカル状態を対象とするため、キャッシュ済みの件名・snippet に対してローカルで行う。

## Consequences

### Positive

- RSS、Reddit、メールで「あとで読む」を保留先として扱う操作モデルが揃う
- Gmail のスターと Yomitori のあとで読むを別目的で利用できる
- Yomitori のあとで読む操作によって Gmail 側へ独自ラベルやスターが追加されない
- Gmail 同期後も Yomitori 独自のあとで読む状態を維持できる
- Gmail 側の過去のアーカイブを初回同期しないため、アカウント追加時の通信量と同期時間を抑えられる
- アーカイブ一覧には Yomitori でアーカイブしたメールだけが残る

### Negative

- あとで読む状態は端末内の Yomitori 固有状態なので、Gmail や他のメールクライアントからは参照できない
- 未読一覧での「スター」は純粋なスター切替ではなく、スター付与時だけ既読化を伴うトリアージ操作として残る
- `archived_locally` と `read_later_locally` という Yomitori 固有の永続状態を管理する必要がある
- Yomitori は Gmail の完全なオフラインメールアーカイブにはならない

## Relationship to existing ADRs

- ADR-0001 の UI / Domain / Data の責務分離を維持する
- ADR-0003 / ADR-0004 に従い、メール固有の状態所有は mail feature 内へ閉じる
- ADR-0006 の background sync / checkpoint / generation の仕組みは維持し、ローカル所有状態を持つスレッドを generation cleanup から保護する
- ADR-0015 の共通 `SwipeActionListItem` を利用し、距離ベースのスワイプ semantics を機能横断で揃える
- ADR-0019 に従い「未読・あとで読む・スター・アーカイブ」をメール feature の下部タブとして表示する
- ADR-0025 の統合ビューではメールの「後で処理する」操作をスターではなく本 ADR のあとで読む状態へ委譲する
