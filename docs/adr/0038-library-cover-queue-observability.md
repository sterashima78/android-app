# ADR-0038: 表紙取得キューを既存DBと WorkManager から可視化する

- Status: Accepted
- Date: 2026-08-14
- Refines: ADR-0006, ADR-0036, ADR-0037

## Context

Kindle と Audible の表紙補完は WorkManager でバックグラウンド実行しているが、ユーザーからは現在取得中なのか、何件待っているのか、取得結果がどうなったのかを確認できない。

現在の実装では書籍単位のキューテーブルは存在しない。WorkManager は実行ジョブを永続化し、各 Worker は `library_items` と `library_item_external_metadata` からその時点の取得対象を選択する。この構造で十分に再開可能であり、別のキューテーブルを追加すると同じ状態を二重管理することになる。

## Decision

蔵書画面の「設定」タブに「表紙取得状況」を追加し、Kindle / Audible の表紙補完状態を確認できるようにする。表紙取得は蔵書固有の設定・診断情報であるため、アプリ全体の設定には重複した導線を置かない。

書籍単位の待機状態は専用テーブルへコピーせず、`library_items` と `library_item_external_metadata` から再構成する。

- 元データに表紙がある場合は「元データに表紙あり」
- 外部メタデータに表紙がある場合は「取得済み」
- 表紙がなく、未試行または再確認期限を過ぎた場合は「取得待ち」
- 最近の `NOT_FOUND` は「見つからない」
- 最近の `AMBIGUOUS` は「候補を特定できない」

再確認期限は ADR-0036 / ADR-0037 と同じ 30 日とする。

実行状態は WorkManager の unique work を監視し、「開始待ち」「取得中」「通信エラー後の再試行待ち」「エラー」を表示する。Kindle の表紙補完を無効化している場合は「停止中」と表示する。

「未取得を再試行」はユーザーの明示操作とし、取得済み表紙を保持したまま未取得結果だけをリセットして WorkManager へ再投入する。Kindle が無効な場合は Audible だけを再投入する。

「実行をキャンセル」は現在の unique work をキャンセルするだけで、表紙補完設定を変更しない。蔵書画面の初期表示や次回インポートなど既存の通常トリガーが発生すれば再度スケジュールされる。

表紙取得画面に表示する書名、ASIN 等は端末内だけで扱い、ログ、fixture、ADR、公開リポジトリへ実ユーザーデータを追加しない。

## Consequences

### Positive

- アプリを終了しても WorkManager の実行状態とDBから取得待ちを復元できる
- 書籍単位のキューを二重管理せずに状態を確認できる
- Kindle / Audible の取得状況を蔵書機能の設定から確認できる
- 未取得結果を30日待たずにユーザー操作で再試行できる
- 現在のバックグラウンド取得をユーザーが停止できる

### Negative

- 書籍単位の「現在まさにHTTP取得中」は永続化しないため、処理中表示はサービス単位になる
- 明示的な履歴テーブルを持たないため、過去の試行履歴は最新結果より前には遡れない
- 再試行操作では未取得結果の最終試行日時がリセットされる

## Relationship to existing ADRs

- ADR-0006 の WorkManager による再開可能なバックグラウンド処理を維持する
- ADR-0036 の Kindle 表紙補完、外部メタデータキャッシュ、30日後の再確認方針を維持する
- ADR-0037 の Audible 表紙補完と外部メタデータキャッシュを維持する
