# ADR-0110: SMB 蔵書同期で高確度な重複ファイルを除外する

- Status: Accepted
- Date: 2026-08-15
- Refines: ADR-0065

## Context

ADR-0065 では SMB 上の ZIP / CBZ / PDF を 1 ファイル 1 冊として扱い、`sourceId` をサーバ設定 ID と共有内パスから生成している。

この方式では、同じファイルが別ディレクトリに複製されている場合や、同じ共有を複数の SMB サーバ設定から走査した場合に、内容上は冗長なファイルが別々の蔵書として登録されることがある。

一方で、同期時に全書籍を読み取って内容ハッシュを計算すると、ADR-0065 の「同期時には書籍本体をダウンロードしない」という境界を崩し、大きな PDF / ZIP が多い環境で同期時間と LAN 通信量が大きく増える。

## Decision

SMB 同期が正常終了した後、`library_items` に保存された SMB 書籍を対象に高確度な重複だけを除外する。

重複キーは次の組み合わせとする。

- 前後空白を除去し、大文字小文字を無視した書名
- ファイルサイズ
- SMB が返した最終更新時刻
- 書籍形式（PDF / ZIP）

これらがすべて一致した書籍は同一ファイルの冗長コピーとして扱う。パスや SMB サーバ設定 ID は重複キーに含めないため、別ディレクトリや別設定から同じファイルを検出した場合も統合できる。

代表として残す書籍は同期順に依存させず、共有内パスの階層が浅いもの、パスが短いもの、パスの辞書順、`sourceId` の順で決定する。バックアップ用の深いディレクトリより通常の配置を優先しつつ、同じ入力なら常に同じ `sourceId` を残す。

除外するのは蔵書登録だけであり、SMB 上の実ファイルは削除しない。重複として除外した `sourceId` については `library_items`、非表示状態、シリーズ関連メタデータ、読書用キャッシュ、表紙キャッシュも削除する。

同期結果の `importedCount` は重複除外後に実際に残った冊数を返す。

## Rejected alternatives

### 全ファイルの SHA-256 を同期時に計算する

同一内容を最も厳密に判定できるが、全ファイルの内容を LAN 越しに読み取る必要があり、同期時に書籍本体を取得しない既存方針と両立しないため採用しない。

### 書名だけで重複判定する

同名の別版や別巻を誤って除外する可能性が高いため採用しない。

### 書名とサイズだけで重複判定する

更新された別内容のファイルを誤判定する余地が残るため、最終更新時刻も一致条件に含める。

## Consequences

### Positive

- 同じファイルが複数パスや複数 SMB 設定から見えても蔵書には原則 1 冊だけ表示される
- 同期時に書籍本体を追加で読み取らないため、既存の同期コストをほぼ維持できる
- 重複判定が保守的なので、別内容の書籍を誤って隠す可能性を抑えられる
- SMB 上の実ファイルは変更しないため、同期処理が破壊的操作にならない

### Negative

- 同じ内容でもファイル名を変更したコピー、更新時刻が変化したコピーは重複として検出しない
- 内容そのものを比較していないため、メタデータが偶然完全一致する別ファイルを理論上は区別できない

より強い重複検出が必要になった場合は、全体ダウンロードではなくファイル先頭・末尾の限定範囲を使う内容フィンガープリントを別途検討する。
