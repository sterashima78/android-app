# ADR-0050: RSSの「あとで読む」を任意で自動要約する

- Status: Superseded by ADR-0030
- Date: 2026-08-13

## Context

RSSの記事は、未読一覧や統合ビューから「あとで読む」に振り分けた後で読む運用を想定している。一方、要約は記事ごとの明示操作で要約タスクキューへ投入するため、「あとで読む」に振り分けた記事を後から個別に要約開始する操作が必要だった。

「あとで読む」は後で内容を確認する意思を表す状態であり、ローカルAIによる要約を利用する場合は、この状態への遷移を要約準備のトリガーとして扱うと追加操作を減らせる。ただし、モデルを利用したくない場合や端末負荷を抑えたい場合もあるため、常時有効にはしない。

ADR-0003では feature 間依存を layer 境界に反しない範囲で許可し、`:app` は composition root とする方針を採用している。今回の動作は RSS の振り分け操作と Summary の要約キューを連携させるため、この方針の範囲で実装する。

## Decision

RSSの記事を「あとで読む」にしたとき、自動的に要約を要求する設定を追加する。

### 1. 自動要約は opt-in とする

設定画面の「要約」セクションに「あとで読む記事を自動要約」を追加する。

初期値は無効とし、有効化後に RSS の記事を「あとで読む」にした場合だけ自動要約を要求する。設定を有効にした時点で既存の「あとで読む」記事を一括投入することはしない。

### 2. 設定の ownership は Summary とする

自動要約設定は要約処理を開始する条件であるため、Summary feature が所有する。

`SummaryRepository` は要約要求、「あとで読む」の自動要約設定の取得・更新を提供する。Data 実装はアプリ内部の `SharedPreferences` に設定を保存する。

### 3. RSS の「あとで読む」確定後に要約を要求する

`RssViewModel` は Bookmark の「あとで読む」更新が成功した後に自動要約設定を確認し、有効な場合に `SummaryRepository.request(articleId, false)` を呼ぶ。

Reddit など RSS feature 以外の「あとで読む」操作には適用しない。

### 4. 既存の要約状態を尊重する

通常の要約要求と同じ重複排除を利用する。

- 要約済みなら新しいタスクを作らない
- queued / running なら新しいタスクを作らない
- 過去の要約が failed の場合は `forceRefresh = true` で再投入を試みる

### 5. 自動要約の失敗で「あとで読む」を巻き戻さない

「あとで読む」登録と自動要約は異なる成功条件とする。自動要約だけが失敗した場合も「あとで読む」状態を維持する。

## Consequences

### Positive

- RSSの「あとで読む」記事の要約準備を自動化できる
- 既存のSummaryキューを再利用できる
- 自動要約失敗がRSSの振り分け操作を破壊しない

### Negative

- RSS UI が Summary Domain に依存する
- 自動要約設定を別途管理する必要がある

## Relationship to existing ADRs

- ADR-0003 の feature 間依存と composition root の方針に従う
- ADR-0030 により、RSS固有の opt-in 自動要約から通常のブックマーク追加時のAI要約・タグ付けへ置き換えられた
