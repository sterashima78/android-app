# ADR-0280: Workout のセット別負荷とフォームを任意で記録する

- Status: Accepted
- Date: 2026-10-09
- Refines: [ADR-0276](0276-workout-ai-review-history.md), [ADR-0131](0131-workout-health-connect-export.md)

## Context

回数・時間・メモだけでは主観的強度、負荷条件、フォーム、実際の休憩を比較できない。レビューは記録されていない値を推定しないため、一次情報の入力能力を拡張する。

## Decision

- Workout Context が所有する `WorkoutSet` に任意の RPE（1〜10）、フォームの状態（安定・崩れ・痛み/違和感）、負荷条件の種類と値、セット前の実休憩秒数を追加する。
- 負荷条件は身体の傾斜、追加重量、補助重量、その他を区別する。重さは kg、身体の傾斜は姿勢を選択式で入力する。種目名から値を推定しない。
- 記録画面では詳細を未入力のまま保存できる。明示的な操作で同一種目の前回の負荷条件のみ再利用できる。RPE・フォーム・実休憩は再利用しない。
- タイマー設定値やセット間のタイムスタンプ差は実休憩として保存しない。未入力の休憩時間を AI が推定しない。
- 永続 payload のバージョンを4とし、3および既存の2は新しい項目を未入力として解釈する。未知バージョンは拒否する。後方互換の終了条件は既存方針を維持する。
- AIのメニュー提案とレビューでは、保存済みの実測・主観記録を一次情報として渡し、異なる負荷条件の回数を単純比較しない。外部運動履歴への export 契約は変更しない。
- 既存の feature-owned 保存領域とバックアップを利用し、別のデータ管理や cross-context import を増やさない。

## Consequences and verification

Workout Domain / UI / Data とAI入力、履歴テキスト、互換性テストを更新する。新しい module、permission、table、Worker、外部送信先は設けない。セットの任意値・復元・旧バージョン・AI入力境界を検査する。

## Compatibility retirement (2026-10-10)

現行の更新互換性baselineはversion 4 payloadであり、version 2/3の一時decoderと専用fixture/testを退役した。未知・旧versionは拒否して元データを保持する。現行payloadの破損時も暗黙に空状態へ置換しない（ADR-0281）。

## Compatibility correction (2026-10-13)

2026-10-10の互換読込退役後も、端末にversion 3のWorkout stateが残っており、Calendarのread-only projectionが`WorkoutReader.load()`で失敗する事象を確認した。version 3はversion 4と同じ基本構造を持ち、version 4で増えたセット詳細は任意項目であるため、version 3の読込を復元し、欠落した詳細を未入力として扱う。読込時に保存済みpayloadを変更せず、次の通常保存時にversion 4へ収束させる。version 2は引き続き非対応とし、version 3でも主要必須field欠落・不正entryは例外として元データを保護する。旧形式の読込を再び退役するのは、現行端末の保存状態がversion 4へ収束したことを確認してからとする。

## 休憩入力の初期値に関する追記 (2026-10-14)

- セット記録画面の「直前の休憩」には、選択中のインターバル設定秒数を初期入力する。インターバル設定変更、種目変更、セット記録後にも次回の入力値を同期する。
- 入力値はユーザーが編集・空欄化できる。空欄のセットは従来どおり未記録として保存する。手動で設定した値をセット記録時に保存し、記録後は設定秒数に戻す。
- これは入力補助であり、タイマー値を実測時間として検証・測定したことを意味しない。保存形式や既存履歴の値は変更しない。初期値で保存された休憩も計測による実測と断定しない。
- 変更は既存Workout UI stateとViewModelに限定し、新しい永続状態や権限を導入しない。
