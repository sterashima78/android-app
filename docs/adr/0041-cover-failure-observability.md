# ADR-0041: 表紙取得失敗を再現可能な情報で観測する

- Status: Accepted
- Date: 2026-08-14
- Refines: ADR-0038

## Context

表紙取得状況は確認できるが、失敗後に原因を調べるための情報が不足していた。Kindle は再試行上限後の通信例外を破棄し、Audible は通信例外を無期限に再試行していた。

## Decision

- `library_item_external_metadata` に nullable な `diagnostic_detail` を後方互換で追加する。
- Kindle / Audible は通信例外を2回まで再試行し、上限到達時に例外メッセージを保存して後続項目へ進む。
- 診断詳細は2,048文字までとし、URL中の一般的な認証パラメータは伏字化する。
- ヘッダー、Cookie、Authorization、HTML/APIレスポンス本文は自動保存しない。
- 表紙取得状況では未取得を既定表示し、sourceId、取得経路、実エラーまたは推定原因、再調査対象を表示する。
- 調査時は画面情報を共有し、sourceId と取得経路から外部サービスの現在の応答を再取得する。

## Consequences

失敗した商品を特定して再現しやすくなり、Audible の1件の恒久的エラーでキュー全体が止まり続けることも避けられる。一方、取得時点のレスポンス本文は保持しないため、現在の応答と取得時点の応答が異なるケースは完全には再現できない。

実例でレスポンス本文が不可欠と分かった場合のみ、明示操作で生成する一時診断バンドルを別途検討する。実ユーザーの蔵書情報や取得データをリポジトリへ追加しない。
