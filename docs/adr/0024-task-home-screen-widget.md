# ADR-0024: タスクをホーム画面ウィジェットから確認・完了できるようにする

## Status

Accepted

## Context

タスク機能はアプリ内でのみ参照・更新できるため、未完了タスクを確認するたびにアプリを開く必要がある。
既存のRSS未読記事には Android の `AppWidgetProvider` / `RemoteViewsService` を利用したホーム画面ウィジェットがあり、ウィジェット用の見た目や更新方式をすでに持っている。

タスクは親子構造と期日を持つため、ウィジェットでも単純なフラット一覧ではなく、既存の `taskTreeRows` による並び順と階層を維持する必要がある。
また、ホーム画面から完了操作を行った場合は、親子タスクの完了同期など既存のドメイン規則を迂回してはならない。

## Decision

- タスクウィジェットは既存の未読記事ウィジェットと同じ `feature:widget:ui` に実装する。
- `feature:widget:ui` は `feature:task:domain` のみに依存し、タスクのDB実装には依存しない。
- Application が `TaskRepositoryProvider` を実装し、ウィジェットから既存の `TaskRepository` を取得する。
- 表示対象は未完了タスクとし、`taskTreeRows(..., TaskFilter.UNFINISHED, ...)` を利用して親子階層と既存のソート順を維持する。
- ウィジェットではタスク名と期日を表示し、期日超過と当日期限を明示する。
- 完了操作は `TaskRepository.setCompleted` を通す。これにより子タスク・親タスクの完了同期規則をそのまま適用する。
- タスク画面で一覧が更新されたときは `TaskWidgetUpdater` でウィジェットのコレクションを更新する。
- ウィジェット自身の完了操作後にも即時更新する。
- 上記以外の経路でタスクが更新された場合に備え、AppWidget の定期更新間隔を30分とし、手動更新ボタンも提供する。
- ウィジェットのヘッダーまたはタスク行を押すとアプリを起動する。タスク専用ディープリンクは今回のスコープに含めない。

## Consequences

- ホーム画面から未完了タスクを確認し、その場で完了できる。
- ウィジェットの完了操作でもアプリ内と同じタスク階層ルールが保証される。
- Widget UI から Task domain への依存が1本増えるが、Task data への依存は追加しない。
- AIツールなどタスク画面外からの変更は即時通知されない場合がある。その場合も手動更新または最大30分の定期更新で反映される。
- 将来、タスク更新の全経路を即時反映する必要が生じた場合は、Task domain 側に変更通知の抽象を導入し、ウィジェット更新をアプリ層で購読する方式を検討する。
