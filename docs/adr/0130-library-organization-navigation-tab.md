# ADR-0130: 蔵書整理を下部ナビゲーションから開く

- Status: Accepted
- Date: 2026-08-20
- Refines: [ADR-0018](0018-library-bottom-tab-navigation.md)
- Amends: [ADR-0108](0108-library-organization-and-ai-suggestions.md)

## Context

ADR-0018 では蔵書画面を「全体」「シリーズ」「非表示」「設定」の4項目の下部 NavigationBar に分けた。その後、ADR-0108 で蔵書整理を通常の閲覧操作から分離した全画面ワークスペースとして追加し、蔵書画面上のフローティングアクションボタンから開く構成としていた。

整理機能はタグ、コレクション、シリーズ、AI一括整理を扱う主要な蔵書操作になっており、画面上に重なるFABよりも、他の蔵書機能と同じ下部ナビゲーションから到達できる方が入口として一貫する。一方、整理ワークスペース自体を通常の書籍一覧へ混在させる必要はなく、ADR-0108 の責務分離は維持したい。

## Decision

- 蔵書画面の下部 NavigationBar に「整理」を追加し、「全体」「シリーズ」「非表示」「整理」「設定」の順に表示する。
- 従来の「整理」フローティングアクションボタンは削除する。
- 「整理」を選択すると `LibraryOrganizationViewModel` を refresh してから、既存の全画面 `LibraryMetadataManagementDialog` を開く。
- 整理ワークスペースのタグ・コレクション・シリーズ管理、AI一括整理、保存方式は変更しない。
- 整理ワークスペースを閉じた場合は、開く前に表示していた蔵書タブへ戻る。整理は永続的な閲覧状態ではなく、下部ナビゲーションから開く管理ワークスペースへの入口として扱う。
- domain/data の契約や永続化形式は変更しない。

## Consequences

### Positive

- 整理機能が蔵書の主要操作として下部ナビゲーションから直接見つけられる。
- FAB が書籍グリッドや他の画面要素へ重なる問題をなくせる。
- 通常の閲覧タブと整理ワークスペースの責務分離は維持できる。
- 既存の整理ロジック、AI処理、永続化へ影響を与えずUI導線だけを変更できる。

### Negative

- NavigationBar が5項目になるため、4項目時より各項目の横幅が小さくなる。
- 「整理」は通常タブのように画面内コンテンツを切り替えるのではなく全画面ワークスペースを開くため、他の4項目とは遷移方式が異なる。

## Public repository note

この変更はUI導線だけを扱う。実際の蔵書名、分類体系、ASIN、Personal Document ID、認証情報などのユーザーデータをコード、テスト、ADRへ追加しない。
