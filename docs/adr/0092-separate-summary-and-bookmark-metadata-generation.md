# ADR-0092: 要約生成とブックマークメタデータ生成を分離する

- Status: Accepted
- Date: 2026-08-17
- Supersedes: ADR-0076
- Refines: ADR-0027, ADR-0030, ADR-0067

## Context

ADR-0076では、ブックマーク記事の最終要約、タグ、フォルダ分類を1回のローカルLLM推論へ統合し、`summary`、`tags`、`folder` を持つJSONオブジェクトとして返す方針を採用した。推論回数は削減できる一方、実端末での利用により次の問題が確認された。

- 要約本文はタグやフォルダ名より長く、Markdownの改行、引用、記号などを含み得るため、JSON文字列として正しくエスケープした完全な応答を小型オンデバイスモデルに生成させる負荷が高い。
- 長い `summary` を含むJSONが途中で不正になると、要約本文自体が生成できていても構造化出力全体の解析失敗として扱われ、要約を保存できない。
- ユーザー設定の要約プロンプトがMarkdownなどの出力形式を要求していても、アプリが後置する「JSONだけを返す」という要件と競合し、ユーザー指定の表現形式が弱くなる。
- タグとフォルダ分類は補助メタデータであるにもかかわらず、その構造化出力失敗がユーザー向け要約の可用性まで下げていた。

要約はユーザーが直接読む成果物であり、ユーザー設定プロンプトへの忠実度を最優先にする。一方、タグとフォルダは機械的に保存するため、引き続き構造化出力とスキーマ検証が必要である。

## Decision

### 1. 要約生成にはユーザー設定プロンプトだけを適用する

新規要約では、ADR-0027のDIRECTまたはFINAL生成へユーザー設定の要約プロンプトをそのまま渡す。ブックマークであることを理由に、JSON形式、タグ、フォルダ、候補一覧などの追加出力要件を要約プロンプトへ付加しない。

これにより、Markdown、箇条書き、見出しなど、ユーザーがカスタムプロンプトで指定した出力形式を要約本文にそのまま利用できる。

### 2. 要約は生成直後に保存する

新規要約が生成できた場合は、ブックマークメタデータ生成より先に要約を保存する。後続のタグ・フォルダ生成が失敗しても、生成済み要約を失わない。

`DefaultSummaryRepository` は保存済み要約を失敗タスクより先に返す既存仕様を維持する。そのため、メタデータ生成でタスクが失敗状態になった場合でも、保存済み要約はユーザーへ表示できる。

### 3. タグとフォルダは要約後の1回のメタデータ推論にまとめる

ブックマーク記事では、生成済みまたは保存済みの要約を入力として、タグとフォルダだけを同じ1回の推論で生成する。

```json
{"tags":["タグ1"],"folder":null}
```

タグとフォルダを別々の推論へ戻さない。新規ブックマークは通常「要約1回 + メタデータ1回」の最大2回とし、ADR-0076以前の最大3回より少ない状態を維持する。保存済み要約の補完はメタデータ1回だけとする。

### 4. 厳密なJSON検証はメタデータだけに適用する

JSONスキーマ検証の対象は `tags` と `folder` に限定する。

- キーは `tags`, `folder` のみ
- `tags` は文字列配列で1〜5件
- 既存の正規化規則で空値・重複を除去する
- `folder` は `null` または既存フォルダ候補と正規化一致する文字列
- 候補外フォルダや余分なJSONキーは不正応答として扱う

要約本文はJSONへ内包せず、構造化出力パーサーを通さない。

### 5. メタデータ失敗は要約を巻き戻さない

メタデータ推論またはJSON検証が失敗した場合、タスクの失敗情報は従来どおり記録して再試行可能な状態を維持する。ただし、その前に保存済みの要約は削除・上書き・巻き戻ししない。

これにより、補助分類の失敗と要約そのものの失敗をユーザー体験上切り離す。将来メタデータ専用キューを導入する場合も、この「要約成果物を補助処理に依存させない」境界を維持する。

### 6. 階層要約の本文処理は変更しない

ADR-0027のチャンク分割、reduction、トークン予算管理は維持する。ADR-0076で追加した最終要約向けの分類suffixは使用しないため、分類候補が要約の入力予算やチャンク判定へ影響しない。

### 7. 公開リポジトリへ実ユーザーデータを追加しない

障害の再現テスト、ADR、PR説明には実際の記事タイトル、URL、要約本文、ユーザーのタグ・フォルダ名を追加しない。一般化した固定データだけを使用する。

## Consequences

### Positive

- ユーザー設定の要約プロンプトとMarkdownなどの出力形式を、分類用JSON要件に干渉されず適用できる。
- 長い要約本文をJSON文字列へ内包しないため、構造化出力の破損によって要約全体が失敗する経路を除去できる。
- メタデータ生成が失敗しても、すでに生成できた要約を保持できる。
- タグとフォルダは1回のメタデータ推論へ統合したままなので、ADR-0076以前の3推論構成には戻らない。
- 要約と機械処理用メタデータの責務が明確になり、出力検証を用途ごとに適用できる。

### Negative

- 新規ブックマークのローカルLLM推論はADR-0076の1回から通常2回へ増える。
- メタデータ推論失敗時には要約が存在していてもタスク履歴が失敗状態になる場合がある。
- タグとフォルダは要約本文を主な分類材料とするため、全文を同一推論へ入れる方式より情報量が少なくなる場合がある。

## Relationship to existing ADRs

- ADR-0027の階層要約、トークン予算、本文を無言で切り捨てない方針を維持する。
- ADR-0030の要約キャッシュ、既存タグ再利用、保存時のブックマーク再確認を維持する。
- ADR-0056に従い、要約とブックマーク分類のポリシーは `feature:summary:data` が所有し、`core:ai-runtime` へ機能固有の概念を持ち込まない。
- ADR-0067の未分類ブックマークだけを既存ユーザーフォルダへ割り当てる方針を維持する。
- ADR-0076の「要約・タグ・フォルダを同じJSONへ統合する」決定を廃止し、「タグ・フォルダだけを同じJSONへ統合する」方式へ置き換える。
- ADR-0070およびADR-0071のバックグラウンドAI直列実行・優先度制御は変更しない。
