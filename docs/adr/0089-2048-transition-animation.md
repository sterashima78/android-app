# ADR-0089: 2048 の手を遷移イベントとして可視化する

- Status: Accepted
- Date: 2026-08-17
- Refines: ADR-0088

## Context

ADR-0088 で 2048 を Game feature に追加した初版では、`Game2048State` の盤面が1手ごとに完成状態へ即時置換される。ルールとしては正しいが、複数タイルが同時に移動・結合し、新規タイルも同時に追加されたように見えるため、操作後に「どのタイルがどこへ移動したか」を追いにくい。

UI 側だけで移動前後の数値配列を比較して対応付ける方法は、同じ値のタイルが複数ある場合や結合時に対応関係が曖昧になる。ゲームルール自身は既に移動元と結合先を決定しているため、その情報を状態遷移の副次情報として UI へ渡す方が一意である。

## Decision

- `Game2048State` は安定状態として従来どおり盤面とスコアを表す。
- 1手の実行結果として `Game2048MoveResult` を追加し、移動方向、各タイルの移動元・移動先・結合有無、新規タイル位置、加算スコアを domain から UI へ渡す。
- `Game2048.move()` は既存の安定状態 API として維持し、アニメーションが不要な利用箇所では従来どおり利用できる。UI は `moveWithTransition()` を利用する。
- Compose UI は1手を次の順で表示する。
  1. 移動元から移動先へタイルを約170msで移動する。
  2. 結合タイルと新規生成タイルを約190msで拡大・収束させる。
  3. 安定状態へ確定し、次の入力を受け付ける。
- 結合による得点増加はスコア数値の補間と `+N` 表示で明示する。
- 動かせない方向への入力も無反応にはせず、盤面を入力方向へ小さく押し返す短いフィードバックを表示する。
- アニメーション中は追加の移動入力を受け付けず、domain の安定状態と表示中の遷移が食い違わないようにする。新しいゲーム操作はアニメーションを中断して新盤面へ切り替えられる。
- アニメーション用情報は保存対象にせず、途中保存や外部 I/O の責務は追加しない。

## Consequences

### Positive

- どのタイルが移動・結合したかを視覚的に追える。
- 同値タイルが複数存在しても UI が移動対応を推測する必要がない。
- 無効入力にもフィードバックがあり、操作が認識されたか判断できる。
- 既存の 2048 ルールと安定状態 API を維持できる。

### Negative

- UI が1手の完了通知を ViewModel へ返す必要があり、表示状態が少し増える。
- 1手あたり約360msは次の移動入力を抑止するため、アニメーションなしの場合より最大入力速度は下がる。
- アニメーション途中で画面を離れた場合、戻った際に未完了の遷移を再表示する場合がある。

## Relationship

本 ADR は ADR-0088 の 2048 実装を置き換えず、1手の視覚表現と domain/UI 間の遷移情報を追加する。Game feature の責務境界は ADR-0080 と ADR-0088 のまま維持する。
