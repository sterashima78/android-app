# ADR-0067: 未要約ブックマークをバックグラウンドでAI補完する

- Status: Accepted
- Date: 2026-08-16

## Context

ADR-0030 ではブックマーク追加時に要約とAIタグを生成する方針を採用し、要約処理自体はWorkManagerの永続キューで実行している。一方、モデル未選択時や過去バージョンから引き継いだブックマークなど、保存済みだが要約が存在しない項目を後から自動補完する入口がなかった。

また、ブックマークにはタグだけでなく単一のフォルダ分類がある。ユーザーがすでに整理したフォルダや「あとで読む」などのシステム分類をAIが上書きすると、明示的なユーザー操作を破壊するため、自動仕分けの境界を定める必要がある。

## Decision

### 1. アプリ起動時に未要約ブックマークの検出Workerをunique workとして起動する

`BookmarkAutoEnrichmentBackfillWorker` は保存済みブックマークを列挙し、ADR-0064の自動AI処理除外方針に従ってYouTubeとRedditを除外する。

検出Worker自身はLLM推論を行わない。対象IDを既存の `SummaryQueue` へ一括投入し、要約・タグ付け・仕分けは既存のforeground `SummaryWorker` が逐次処理する。これによりActivityや画面の寿命に依存せず、既存の停止・再開・履歴表示の仕組みを再利用する。

### 2. 自動補完では要約もタスクも存在しない項目だけを新規投入する

一括投入時は次を満たす記事だけを新規タスク化する。

- ブックマークとして保存中
- 自動AI処理の対象URL
- 保存済み要約がない
- `summary_tasks` に既存タスクがない

失敗・停止・キャンセル済みタスクも「既存タスク」として扱い、アプリ起動のたびに自動再試行しない。ユーザーが明示的に再開・再生成する既存操作を優先する。

ローカルAIモデルが未選択の場合は何も投入しない。モデル選択後の次回起動で再評価する。

### 3. 要約生成後にAIタグ付けと既存フォルダへの仕分けを行う

既存のタグ生成は維持する。AIには既存タグをtaxonomy contextとして提示し、既存語で表現可能な場合は既存タグを優先しつつ、必要な場合だけ新規タグを作る。

フォルダ仕分けは次の制約を設ける。

- 対象は現在フォルダ未設定のブックマークだけ
- `system_kind IS NULL` のユーザー作成フォルダだけを候補にする
- AIは候補から1件を選ぶか「なし」を返す
- AIが候補外の名前を返しても新規フォルダは作らない
- 仕分け確定直前にも未分類状態をtransaction内で再確認し、並行するユーザー操作を上書きしない

タグとフォルダに変更があった場合は既存の `DataChangeNotifier` を通知する。

### 4. 公開リポジトリへユーザーデータを出力しない

バックグラウンド処理は既存の端末内ローカルモデルだけを利用し、記事内容、要約、タグ、フォルダ候補を外部AIサービスへ送信しない。

ログ、fixture、テスト、ADR、PR説明には実ユーザーのURL、記事タイトル、タグ名、フォルダ名を含めない。テストデータは一般化した固定文字列だけを使用する。

## Consequences

### Positive

- 過去に要約されなかったブックマークを自動的に補完できる。
- 長時間のAI処理は既存WorkManagerキューへ委譲され、画面を閉じても継続できる。
- 既存タグを再利用しながらタグ付けできる。
- 未分類ブックマークを既存フォルダへ整理できる。
- ユーザーが明示したフォルダ分類や停止済みタスクを自動処理が上書きしない。

### Negative

- フォルダ仕分けのため、対象ブックマークではタグ生成とは別に1回のローカルLLM推論が追加される。
- 既存フォルダに適切な候補がない場合は未分類のまま残る。
- 失敗済みタスクは自動再試行しないため、必要に応じてユーザーがタスク画面から再開する必要がある。

## Relationship to existing ADRs

- ADR-0030: ブックマークの要約・AIタグ付け方針を維持し、未処理項目のバックフィルとフォルダ仕分けを追加する。
- ADR-0051: 要約処理を永続バックグラウンドキューへ載せる方針を再利用する。
- ADR-0064: YouTube/Redditを自動AI処理から除外する判断を維持する。
- ADR-0066: 長時間のローカルAI処理をUI寿命から分離しWorkManagerへ委譲する考え方を共有する。一方、ブックマークのタグ付け・既存フォルダ仕分けは既存の自動適用仕様を維持する。
