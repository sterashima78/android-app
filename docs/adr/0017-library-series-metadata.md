# ADR-0017: 蔵書のシリーズ情報を同期キャッシュから分離して管理する

- Status: Accepted
- Date: 2026-08-10
- Amended: 2026-08-10

## Context

蔵書が増えると、同じ作品の複数巻がフラットなグリッドに並び、一覧性が低下する。シリーズ単位でまとめて折りたためる表示と、シリーズ内の巻数・表示順を管理する機能が必要になった。

ADR-0013 では `library_items` を外部サービスから再構築可能な同期キャッシュとして扱う。ADR-0014 でも、ユーザーが編集する非表示状態は同期キャッシュと分離して保存している。

Google Books API の公開 Volume リソースには、アプリが安定して依存できるシリーズ識別子・シリーズ順の標準フィールドが文書化されていない。そのため外部サービスの未保証メタデータはシリーズ情報の正規データとして利用しない。

一方、このアプリは個人利用を前提としており、蔵書タイトルではシリーズ巻数がタイトル末尾の連続数字またはカッコ付き数字として表現されるケースが多い。すべてのシリーズを手入力する負担を避けるため、この表記を明示的なヒューリスティックとして採用する。

## Decision

シリーズ情報には「自動判定」と「手動設定」の2層を設ける。

### 自動判定

手動シリーズが設定されておらず、自動判定から除外されていない書籍について、タイトル末尾を次の規則で解析する。

- 末尾が連続した半角または全角数字なら、その数字を巻数、直前までをシリーズ名とみなす
- 末尾が半角 `()` または全角 `（）` で囲まれた数字なら、その数字を巻数、カッコ直前までをシリーズ名とみなす
- シリーズ名末尾の空白と一般的な区切り文字 `-`, `#`, `:`, `：` などは除去する
- 巻数は1以上の整数とする
- 推定された同一シリーズが複数冊ある場合に自動グループを作る
- 同名の手動シリーズが既に存在する場合は、自動判定対象が1冊でもそのシリーズへ合流できる

自動判定結果は永続化しない。`library_items` のタイトルから一覧生成時に導出する表示用メタデータとする。これにより同期キャッシュを汚染せず、タイトルが変化した場合も再判定できる。

### 手動設定

ユーザーがシリーズ名や巻数を保存した場合は、従来通り `library_items` から分離した `library_item_series` に保存する。

```text
library_item_series
- source
- source_id
- series_name
- series_position nullable
- updated_at
- PRIMARY KEY(source, source_id)
```

手動設定は常に自動判定より優先する。自動判定されたシリーズを編集して保存した場合も、その書籍は以後手動設定として扱う。

ユーザーが「シリーズ解除」を行った書籍は、自動判定によって直後に同じシリーズへ戻らないよう `library_item_series_exclusions` に保存する。

```text
library_item_series_exclusions
- source
- source_id
- updated_at
- PRIMARY KEY(source, source_id)
```

その書籍へ再び手動シリーズを保存した場合は除外状態を解除する。

書籍の識別には ADR-0013 / ADR-0014 と同じ `LibrarySource` と source-specific ID の組を使用する。`library_item_series` と `library_item_series_exclusions` には `library_items` への外部キーを設けない。同期元から一時的に書籍が消えたり、同期処理が `library_items` を置換したりしても、ユーザーの手動調整を保持するためである。

Domain の `LibraryBook` は UI へ渡す蔵書表現として `LibrarySeries?` と、自動判定から除外されているかを表す状態を持つ。Data 層は永続化された手動シリーズのみを `LibrarySeries?` として構築し、自動シリーズの推定は UI のグルーピング処理で行う。

シリーズ名は自由入力とし、`series_position` は任意の正整数とする。設定済みの書籍を先に巻数順、未設定の書籍をその後に並べる。

蔵書一覧ではシリーズごとに見出しへまとめ、初期状態は折りたたむ。見出しにはシリーズ名と冊数を表示し、展開すると所属書籍を従来と同じグリッドで表示する。シリーズ未設定の書籍は従来通り個別に表示する。非表示・再表示や Google Play Books の再同期によって手動設定・除外設定は失わない。

## Consequences

### Positive

- 一般的な連番タイトルの多巻シリーズを入力なしでまとめられる
- 自動判定後もシリーズ名・巻数を手動で修正できる
- 誤判定した書籍をシリーズ解除すれば自動判定から除外できる
- 自動判定結果を同期キャッシュへ保存しないため、外部データとユーザー編集情報の責務を維持できる
- Google Play Books の再同期後も手動設定と除外設定を維持できる
- 将来 Kindle / Audible を追加しても同じ source/source ID モデルを利用できる

### Negative

- タイトル末尾の数字が巻数でない書籍は誤判定する可能性がある
- タイトル表記が異なるシリーズは自動では同一グループにならない
- 自動判定規則に含まれない「第3巻」「Vol.3」などは手動設定が必要になる
- source-specific ID が変化した場合は手動設定・除外設定の移行が必要になる

## Rejected alternatives

### 自動推定結果を `library_item_series` に保存する

推定結果とユーザーが明示した設定の区別が失われ、判定規則を改善した際に再計算しにくくなる。また同期元タイトルの更新との整合も複雑になるため採用しない。

### `library_items` に series 列を追加する

同期時の置換でユーザー設定が失われるか、同期処理がローカル編集状態の引き継ぎ責務を負うことになるため採用しない。

### 誤判定を避けるため自動推定を行わない

以前はこの方針を採用していたが、個人利用アプリとして手入力負担の方が大きいと判断した。末尾連番を巻数とみなすという明示的な前提を受け入れ、手動上書きと自動判定除外で誤判定を修正できる構成へ変更する。

## Relationship to existing ADRs

- ADR-0013 の「`library_items` は再構築可能な同期キャッシュ」という判断を維持する
- ADR-0014 の「ユーザー編集状態を同期キャッシュから分離する」方針をシリーズの手動設定・自動判定除外にも適用する
- ADR-0003 / ADR-0004 に従い、シリーズ管理は `library` feature の domain/data/ui 内で完結させる
- `core:database` は引き続き汎用 capability とし、蔵書固有スキーマを持たせない
