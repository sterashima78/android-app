# ADR-0017: 蔵書のシリーズ情報を同期キャッシュから分離して管理する

- Status: Accepted
- Date: 2026-08-10

## Context

蔵書が増えると、同じ作品の複数巻がフラットなグリッドに並び、一覧性が低下する。シリーズ単位でまとめて折りたためる表示と、シリーズ内の巻数・表示順を管理する機能が必要になった。

ADR-0013 では `library_items` を外部サービスから再構築可能な同期キャッシュとして扱う。ADR-0014 でも、ユーザーが編集する非表示状態は同期キャッシュと分離して保存している。

Google Books API の公開 Volume リソースには、アプリが安定して依存できるシリーズ識別子・シリーズ順の標準フィールドが文書化されていない。このため、タイトル文字列からシリーズを推測したり、未保証の外部メタデータへ依存したりすると、誤分類や API 変更による破損が起きやすい。

## Decision

シリーズ情報はユーザーがアプリ内で明示的に設定するローカルメタデータとし、`library_items` から分離した `library_item_series` に保存する。

```text
library_item_series
- source
- source_id
- series_name
- series_position nullable
- updated_at
- PRIMARY KEY(source, source_id)
```

書籍の識別には ADR-0013 / ADR-0014 と同じ `LibrarySource` と source-specific ID の組を使用する。

`library_item_series` には `library_items` への外部キーを設けない。同期元から一時的に書籍が消えたり、同期処理が `library_items` を置換したりしても、ユーザーが設定したシリーズ情報を保持するためである。同じ source/source ID の書籍が再度同期された場合は、保存済みシリーズ情報を再び結合して表示する。

Domain の `LibraryBook` は、外部メタデータそのものではなく UI へ渡す蔵書表現として `LibrarySeries?` を持つ。Data 層は `library_items` と `library_item_series` を結合してこの値を構築する。外部サービスから同期した直後の `LibraryBook` はシリーズ未設定でもよく、保存時に外部キャッシュへシリーズ情報を書き戻さない。

シリーズ名は自由入力とし、既存シリーズ名を再利用できる UI を提供する。`series_position` は任意の正整数とし、設定済みの書籍を先に巻数順、未設定の書籍をその後に並べる。

蔵書一覧ではシリーズごとに見出しへまとめ、初期状態は折りたたむ。見出しにはシリーズ名と冊数を表示し、展開すると所属書籍を従来と同じグリッドで表示する。シリーズ未設定の書籍は従来通り個別に表示する。非表示一覧でも同じシリーズ情報を利用し、非表示・再表示によってシリーズ設定は失わない。

## Consequences

### Positive

- 多巻シリーズを一つの見出しへ畳めるため、蔵書一覧を短く保てる
- 外部サービスのシリーズメタデータ品質や仕様変更に依存しない
- Google Play Books の再同期後もシリーズ設定を維持できる
- 非表示状態と同様に、外部キャッシュとユーザー編集情報の責務を分離できる
- 将来 Kindle / Audible を追加しても同じ source/source ID モデルを利用できる

### Negative

- 初回のシリーズ分類はユーザーが設定する必要がある
- 同じシリーズ名の表記揺れは自動統合しない
- source-specific ID が変化した場合はシリーズ設定の移行が必要になる
- 将来、信頼できるシリーズメタデータを提供する同期元を追加した場合、ローカル設定との優先順位を別途決める必要がある

## Rejected alternatives

### タイトル文字列からシリーズ名と巻数を自動推測する

出版社・電子書籍ごとにタイトル表記が異なり、作品名に数字を含むケースも多いため、誤分類を避けにくい。補助候補として将来追加する余地は残すが、永続化する正規データにはしない。

### `library_items` に series 列を追加する

同期時の置換でユーザー設定が失われるか、同期処理がローカル編集状態の引き継ぎ責務を負うことになるため採用しない。

## Relationship to existing ADRs

- ADR-0013 の「`library_items` は再構築可能な同期キャッシュ」という判断を維持する
- ADR-0014 の「ユーザー編集状態を同期キャッシュから分離する」方針をシリーズ情報にも適用する
- ADR-0003 / ADR-0004 に従い、シリーズ管理は `library` feature の domain/data/ui 内で完結させる
- `core:database` は引き続き汎用 capability とし、蔵書固有スキーマを持たせない
