# ADR-0074: 蔵書メタ情報を分類軸から編集しシリーズ単位で再整理できるようにする

- Status: Accepted
- Date: 2026-08-16
- Amended: 2026-08-16

## Context

ADR-0111 では、一括蔵書AI整理を承認待ちにせず自動反映する代わりに、確定済みのタグ・コレクションを後から人が効率よく修正できる編集ワークフローを別途用意する方針を採用した。

従来の蔵書整理画面は書籍を起点に1冊ずつ編集する構成である。この構成では、特定タグやコレクションに誤って入った書籍を見つけて外す操作や、シリーズ全体の分類を見直す操作に手数がかかる。

また既存の一括AI整理は「未整理の蔵書」を対象とし、整理済み書籍を自動で上書きしない。これは通常の自動整理としては安全だが、人が明示的にシリーズ全体を再解析したい場合には利用できない。

初期のメタ情報管理UIでは、タグまたはコレクションごとのカード内へ所属書籍をすべて展開していた。分類数や所属冊数が増えると、特定の分類を探すために大量の書籍行をスクロールする必要があり、整理画面を蔵書閲覧の入口として使いにくい。

## Decision

### 1. 「整理」をメタ情報管理ハブとして扱う

蔵書画面の「整理」から、タグ・コレクション・シリーズを切り替えて確認できる管理画面を開く。

この画面はAI整理を開始するだけの画面ではなく、確定済みの分類から蔵書を閲覧し、人が分類状態を継続的に調整するための管理ハブとする。

従来の書籍単位編集および一括AI整理は削除せず、管理画面から「AI一括整理」として遷移できるようにする。

### 2. タグ・コレクションは分類一覧から専用の蔵書ページへ遷移する

タグ画面ではタグごと、コレクション画面ではコレクションごとに分類カードを表示する。分類カードには分類名、所属冊数、先頭数冊のプレビューだけを表示し、全所属書籍は展開しない。

分類を選択すると、その分類だけを対象にした詳細ページを同じ全画面管理ワークスペース内で開く。詳細ページでは所属書籍を遅延リストで表示し、各書籍について現在のタグとコレクションも確認できるようにする。

詳細ページから各書籍を1操作で対象分類から外せるようにする。タグ詳細では「タグを外す」、コレクション詳細では「コレクションから外す」と操作対象を明示し、曖昧な「外す」だけのラベルは使わない。

更新は新しいDB操作を直接追加せず、既存の `LibraryOrganizationRepository.save` を通す。対象分類だけを除外した `LibraryOrganizationDraft` を作り、その他のタグ・コレクションと読書状態はそのまま引き継ぐ。

所属解除後は最新snapshotから分類ページを再構成する。最後の1冊を外して分類の所属冊数が0になった場合は分類一覧へ戻す。

この変更ではタグ・コレクションのマスター自体を明示削除する機能は追加しない。所属書籍がなくなった分類は管理画面の一覧から表示しない。

### 3. シリーズ単位のAI再整理を明示操作として提供する

シリーズ画面では、既存のシリーズグルーピングと同じ単位で書籍を表示し、シリーズごとにAI整理を再実行できるようにする。

通常の一括整理とは異なり、これはユーザーが整理済み書籍の上書きを明示的に要求する操作である。そのため `LibraryMetadataOrganizer` が対象書籍を順番に再解析し、生成と検証に成功した書籍だけ `LibraryOrganizationRepository.save` で置き換える。

AI解析が失敗した書籍には保存処理を行わず、既存のタグ・コレクション・読書状態を維持する。成功した場合も読書状態はAIに推測させず、再解析前の値を引き継ぐ。

### 4. シリーズ再整理でも確定済みシリーズ文脈を利用する

ADR-0111 と同じシリーズ一致規則を用い、対象シリーズの別書籍に設定されているタグ・コレクションを `seriesContext` としてAIへ渡す。

両方にseries IDがある場合はID一致を優先し、どちらかにIDがない場合のみ正規化したシリーズ名へフォールバックする。両方に異なるseries IDがある場合は同一シリーズとみなさない。

シリーズ再整理の開始時にsnapshotを1度読み、各書籍で保存に成功した分類はメモリ上の確定コンテキストへ追加する。後続書籍は永続化済みsnapshotとこの確定コンテキストを合わせて参照する。これにより保存成功後のsnapshot再取得失敗を「保存失敗」と誤認せず、先に再整理した書籍の分類も後続書籍へ引き継げる。

### 5. シリーズ再整理は対話操作として扱い、既存バックグラウンドbatchとは競合させない

シリーズ再整理は管理画面から開始する対象限定の対話操作として `LibraryOrganizationViewModel` のscopeで実行する。既存の全蔵書向け一括AI整理は引き続きWorkManagerとdurable batchを利用する。

一括AI解析の実行中はシリーズ再整理を開始できず、シリーズ再整理中も保存・個別AI候補生成・一括AI整理の開始／再開を抑止する。これにより同じ蔵書整理状態を複数経路から同時更新しない。

一括AI整理を一時停止するときは、DB上のbatch状態をPAUSEDにした後、WorkManagerの `cancelUniqueWork` が返すOperationの完了まで待ってからUIへ一時停止完了を反映する。これによりバックグラウンドworkerが推論中のままシリーズ再整理を開始する競合窓を作らない。

ADR-0070 のバックグラウンドAI worker直列化は変更しない。シリーズ再整理はバックグラウンドworkerではないため共通background task gateの対象にはしない。

対象シリーズが非常に大きく、画面離脱やプロセス終了を跨ぐdurabilityが必要になった場合は、将来の変更で「整理済み上書きを許可するdurable batch mode」を追加する。本ADRではDB batch schemaを複雑化せず、明示的な対話操作を優先する。

### 6. 公開リポジトリへ実ユーザーデータを追加しない

テスト、ADR、ログには架空の書名・ID・分類名だけを使用する。実在する蔵書名、ASIN、Personal Document ID、ユーザー固有タグ・コレクション、AI生成結果、認証情報を追加しない。

## Consequences

### Positive

- タグ・コレクション自体を蔵書閲覧の入口として利用できる。
- 1つの分類に大量の書籍が所属しても、他の分類を探すためのスクロール量が所属冊数に比例しない。
- 誤分類をタグ・コレクション側から発見して1操作で修正できる。
- 解除前に対象書籍の他のタグ・コレクションを確認でき、分類体系を見ながら手動調整しやすい。
- 既存の書籍単位編集と一括AI整理を維持したまま、整理画面を管理・閲覧用途へ拡張できる。
- シリーズ全体の分類を明示的に作り直せる。
- AI失敗時に既存分類を失わず、読書状態も維持される。
- 新しいDB schemaやtaxonomy専用更新APIを追加せず既存repository境界を再利用できる。

### Negative

- 個別の分類に属する全書籍を見るには分類一覧から1段遷移する必要がある。
- シリーズ再整理は画面内の対話処理なので、プロセス終了を跨いで再開できない。
- タグ・コレクションのマスター削除や名称変更、一括追加／削除は今回の範囲外である。

## Relationship to existing ADRs

- ADR-0017 / ADR-0039: 既存のシリーズメタデータとシリーズ識別規則を利用する。
- ADR-0054: 蔵書のruntime・UI stateはLibrary featureが所有する方針を維持する。
- ADR-0108: `LibraryOrganizationRepository` と書籍単位の整理モデルを再利用する。
- ADR-0070: durable batchとバックグラウンドAI直列化を維持する。
- ADR-0111: section 5で予定した「自動反映後に人が大量修正する編集ワークフロー」を具体化し、シリーズ文脈の利用規則を継承する。
- ADR-0072: 承認専用UIを復活させず、確定済み整理状態を直接編集する方針を維持する。
