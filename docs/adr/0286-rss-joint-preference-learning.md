# ADR-0286: RSSの優先・除外参考を同時学習する

- Status: Accepted
- Date: 2026-10-15
- Amends: [ADR-0270](0270-rss-recommendation-scoring.md), [ADR-0279](0279-rss-feedback-learning-outcome.md)

## Context

従来の推薦スコアは除外傾向だけから評価し、「除外根拠なし」を10とした。利用者が積極的に読みたい記事と、読まなくてよい記事の両方を指定すると、記事タイトル中の特徴が両方に現れる。正例を優先条件だけに追加すると、既存の除外条件が広すぎる場合に衝突する。

## Decision

- 同じ参考記事入力を `PRIORITY`（優先参考）と `EXCLUSION`（除外参考）で区別し、学習では両方の参考記事と現在の条件を同時に提示する。単一の構造化tool callが「学習した優先条件」「学習した除外条件」「更新結果」を一組で返す。
- 優先参考が除外条件に含まれる特徴を持つ場合、優先条件に例外を追加するだけでなく、除外学習条件の過剰な一般化を同時に修正する。逆の場合も同様。手動除外条件は自動変更しないが、判定では優先・除外参考が示す文脈を踏まえて総合評価する。
- 参考記事は学習後に削除せず、既存のfeedbackテーブル内で処理済みとして保存する。過去の正負参考を有界に抽出して、新規feedbackとともに学習の根拠へ使う。pendingだけがdebounceとretryを発火する。既存レコードは除外参考として移行する。
- 学習toolの `updated` は優先・除外いずれかの学習条件が変化した場合にのみ、`already_covered` はどちらも不変の場合にのみ有効。両条件を原子的に保存し、学習開始後にrevision/providerが変われば結果とpendingの消費を拒否する。
- 推薦スコア1〜10は相対的な読みたい度合いとし、1は低優先、10は高優先。両方の条件を踏まえて評価する。タイトルだけでは衝突を解決できない場合は推測で数値化せず情報不足扱いとする。
- 優先参考登録は記事の未読・保存状態を変更しない。既存の4方向swipeは変更せず、RSS未読と統合ビューの長押しメニューへ追加する。除外参考の既読化は従来どおり維持する。
- 「あとで読む」へのRSS記事追加は既存の保存処理が成功した場合に優先参考にも登録する。RSS未読ウィジェットでは、application compositionが同じRSS推薦サービスへのcallbackを注入する。ウィジェットはRSS以外の記事を優先参考へ渡さず、参考登録に失敗しても保存を取り消さない。
- 個別の学習条件リセットではその種類の処理済み参考を削除し、別種類の参考と未処理の参考を保持する。リセット後の学習が消去済みの例を使って同じ条件を再生成しないようにする。
- 学習では1回最大50件の未処理feedbackを消費する。50件を超える場合はWorkerが残件を確認してretryする。学習と採点は従来のRSS-owned background runtimeを再利用する。実行先の明示選択、cloudへ送る情報をタイトル・条件・直前評価に限定する制約も維持する（優先参考のタイトルも対象に含む）。

## Consequences

- policy/feedbackのカラム追加と最新版データの移行が必要。
- 処理済みの参考記事が残るため、従来より学習入力とバックアップのサイズが増える。有界な参考抽出を行い、promptへ記事IDやURLを送らない。
- 過去に学習済みで削除されたfeedbackは復元できない。現在の学習条件は維持し、以後の参考蓄積に活用する。
- 既存のfeedback debounce / stale result / retryの状態機械は種類によらず同一である。
