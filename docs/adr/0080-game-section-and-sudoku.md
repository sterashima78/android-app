# ADR-0080: 一人用ゲームを独立した Game feature として追加する

- Status: Accepted
- Date: 2026-08-16

## Context

アプリに一人用ゲームを継続的に追加するため、「ゲーム」という独立したセクションが必要になった。初期ゲームとして数独を実装する。

ゲームは RSS、蔵書、AI など既存 feature のデータや外部サービスには依存しない。一方、数独には問題・解・入力・完成判定という UI から独立したルールがあるため、これらを app module や Compose UI に直接埋め込むとテストと今後のゲーム追加が難しくなる。

## Decision

- navigation drawer に `ゲーム` セクションを追加する。
- ゲーム一覧と各ゲームの画面遷移は `:feature:game:ui` が所有する。
- 数独の問題表現、問題生成、入力規則、完成判定は `:feature:game:domain` が所有する。
- 現時点では永続化や外部 I/O がないため `:feature:game:data` は作らない。ADR-0003 の「必要な layer だけを module 化する」方針に従う。
- 数独の初期問題は解が一意な既知の盤面を基底とし、新しい問題を作る際は数字の置換、3行単位の band と band 内行の入れ替え、3列単位の stack と stack 内列の入れ替え、転置を組み合わせる。これらは数独の制約と解の一意性を保存するため、端末上で解探索を行わず即時生成できる。
- 誤入力は盤面へ確定せず、ミス回数として数える。正解入力だけを盤面へ反映する。
- ゲームの進行状態は `SudokuViewModel` が保持し、Game feature 内で一覧へ戻っても保持する。アプリ終了後の継続保存は初版の対象外とする。

## Consequences

### Positive

- 今後の一人用ゲームを `GameRoute` の一覧へ追加できる。
- 数独ルールが Android / Compose から独立し、JVM unit test で検証できる。
- 問題生成時の探索処理がなく、端末性能に依存しにくい。
- 保存領域やネットワーク権限を増やさない。

### Negative

- 初版は難易度選択、候補メモ、ヒント、途中保存を持たない。
- 基底問題の同型変換なので、見た目の問題数は多いが論理構造の種類は1つである。

## Relationship

ADR-0003 の feature-first / 必要な layer のみ作る方針、および app は navigation と composition root に限定する方針を継承する。
