# ADR-0230: 複数資料で再現するタグだけを自動Knowledgeトピックへ昇格する

- Status: Accepted
- Date: 2026-09-01
- Refines: [ADR-0030](0030-bookmark-ai-enrichment.md), [ADR-0109](0109-generated-knowledge-wiki.md), [ADR-0227](0227-partition-auto-wiki-generation-by-topic.md)

## Context

ADR-0030では、ブックマーク追加時のAIメタデータ生成で既存タグを優先して再利用しつつ、既存タグで表現できない概念には新しいタグを生成できる。Bookmarkの検索性を高める目的では細かなタグも有用だが、AIが記事固有の概念を新規タグとして返す場合があり、結果として関連資料が1件だけのタグが多数作られることがある。

ADR-0109以降の自動Knowledge Wikiは、タグがある資料をタグ単位のトピックへ最優先で分類する。従来はタグの利用件数に下限がなかったため、1件だけのAI生成タグでも独立したKnowledgeページ候補になった。タグ生成が細分化するほどKnowledgeページ数とバックグラウンド生成タスク数も増え、個々のページは1資料の要約を言い換えるだけになりやすい。

Bookmarkのタグは検索・整理用メタデータであり、Knowledgeの自動Wikiトピックは複数資料から知識を統合する単位である。この2つに同じ粒度を要求する必要はない。

## Decision

### 1. タグトピックは3件以上の要約済み資料で再現した場合だけ昇格する

自動Wikiのトピック計画時に、要約済み保存資料全体から正規化タグごとの異なるarticle ID数を数える。

- 3件以上の資料に付与されているタグだけを自動Knowledgeのタグトピック候補にする。
- 1〜2件しかないタグはBookmark上ではそのまま保持し、検索・分類には引き続き利用する。
- 閾値判定はsource上限で切り詰める前の全source snapshotに対して行う。
- 同一記事に同じタグの表記ゆれが複数存在しても、1記事として数える。

3件という値は、単発・偶発的な細分化タグを除外しつつ、繰り返し現れる関心テーマを早い段階でWiki化する初期基準とする。将来の実データで不足が確認された場合は別の判断として変更する。

### 2. 昇格タグがない資料はフォルダ、提供元へフォールバックする

各資料についてKnowledgeトピック候補を次の順で決める。

1. その資料に3件以上の利用実績を持つタグが1件以上あれば、該当タグ単位
2. 該当タグがなく通常ブックマークフォルダがあれば、フォルダ単位
3. どちらもなければ、提供元単位

資料が昇格済みタグと閾値未満タグの両方を持つ場合は、昇格済みタグだけを採用し、フォルダ・提供元へ追加で重複配置しない。同一資料が複数の昇格済みタグを持つ従来の複数トピック所属は維持する。

### 3. 既存の自動生成ページ整理を利用する

閾値導入によってトピック集合から消えた1〜2資料タグ由来の自動生成ページは、既存の `deleteObsoletePages` 経路で整理する。

`editor_managed = true` のページはユーザー編集済み資産であり、自動トピック集合から消えても従来どおり削除しない。今回DB schemaやページownershipは変更しない。

### 4. Bookmarkの自動タグ生成policy自体は今回変更しない

ADR-0030の既存タグ優先、新規タグ許可、手動タグとAIタグを同じ体系へ保存する判断は維持する。今回の目的はKnowledgeページ量産を止めることであり、タグ候補の保留・昇格用テーブルやprovenance追加までは行わない。

将来、Bookmarkのタグ一覧自体が細分化しすぎることが継続的な問題になった場合は、「AI新規タグを候補状態で保持し複数記事で再現したら正式タグへ昇格する」方式を別ADRで検討する。

## Consequences

### Positive

- 1記事だけのAI生成タグから独立Knowledgeページが量産されなくなる。
- 自動Wikiの各タグページが複数資料の統合というKnowledge本来の用途に近づく。
- タグ数が多くてもKnowledge topic worker数が直接増えにくくなり、ADR-0229のruntime pressure対策を補完できる。
- 細かなタグはBookmark検索には残るため、Knowledge都合で検索用メタデータを失わない。
- DB migrationやタグprovenance導入なしで適用できる。

### Negative

- 重要でも保存資料が1〜2件しかないテーマは、自動タグページとしては生成されない。
- その資料はフォルダまたは提供元トピックへ統合されるため、Knowledge上の粒度が一時的に粗くなる。
- タグ利用件数が3件を跨ぐとトピック集合が変化し、新規ページ生成またはobsolete page整理が発生する。
- Bookmarkタグ一覧そのものの細分化は今回解消しない。

## Alternatives considered

### AIへ新規タグ生成を禁止する

タグ体系の増殖は最も強く抑えられるが、新しい関心テーマを自動発見できなくなる。Bookmarkの検索性とKnowledgeのトピック粒度は別問題として扱うため採用しない。

### 1件タグをそのままKnowledge化し、生成タスクだけ遅延する

実行負荷は平準化できるが、1資料を言い換えただけのWikiページが増える品質問題を解消しないため採用しない。

### AI新規タグを候補テーブルへ保存して3件で正式昇格する

根本的にタグ体系を整理できる可能性があるが、Bookmarkの永続モデル、AIタグと手動タグの区別、候補のlifecycle管理が必要になる。今回の問題に対して変更範囲が大きいため後続検討とする。

## Verification

- 3資料以上で使われるタグだけがtag topicになることをunit testする。
- 1〜2資料のタグしか持たない資料がfolderへフォールバックすることをunit testする。
- folderがない場合にsourceへフォールバックすることをunit testする。
- 昇格タグと閾値未満タグを同時に持つ資料がfolder/sourceへ重複しないことをunit testする。
- 既存Knowledge data test、architecture checks、public repository checks、lintをPR CIで実行する。
