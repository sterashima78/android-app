# ADR-0086: ブックマークタグは高密度一覧からボトムシートで内容を閲覧する

- Status: Accepted
- Date: 2026-08-17

## Context

ブックマークのタグ管理画面は、タグを横一列の `LazyRow` に並べ、選択したタグの記事一覧を同じ画面下部へ表示していた。タグ数が少ない間は単純だが、タグが増えると横スクロールを繰り返して目的のタグを探す必要があり、タグ全体の一覧性が低下する。

タグ画面の主目的は、多数のタグから対象を素早く見つけることである。一方、タグに属するブックマーク一覧やタグ名変更・削除は、対象タグを選んだ後に必要になる詳細操作であり、常時タグ一覧の表示領域を消費する必要はない。

## Decision

- タグ管理画面の主要領域は `LazyVerticalGrid` による高密度なタグ一覧とする。
- 列数は固定せず `GridCells.Adaptive` を使用し、タグセルの最小幅を 88dp とする。スマートフォンの横幅を可能な限り複数列へ利用しつつ、タグ名と記事数を一行で表示できる幅を確保する。
- タグは保存層が返す `normalized_name` 順を維持し、追加の並び替え状態は UI に持たない。
- 各タグセルにはタグ名と対象ブックマーク件数を表示し、長いタグ名は一行で省略する。
- タグを選択したときだけ Material 3 の `ModalBottomSheet` を表示し、そのタグに属するブックマークを既存の `ArticleList` で表示する。
- ボトムシートは画面高の最大 90% を使用し、一覧を十分に閲覧できる領域を確保する。
- タグ名変更とタグ削除は選択中タグのボトムシートヘッダーから行う。タグ作成 UI はタグ一覧上部に残す。
- ブックマーク解除、記事を開く、要約、タグ編集、フォルダ移動、コンテンツ種別変更は既存の `ArticleList` の操作を再利用し、新しい操作系を導入しない。
- 非表示中の記事をタグ件数と一覧の両方から除外する既存の挙動は維持する。

## Consequences

### Positive

- 同じ画面面積で同時に確認できるタグ数が大幅に増え、タグ数が多い場合の探索が容易になる。
- タグ一覧とブックマーク詳細の表示責務が分かれ、タグを探している間は記事一覧が画面を占有しない。
- 画面幅に応じて列数が自動調整されるため、端末サイズごとの固定レイアウトを持たずに密度を高められる。
- 記事一覧と既存アクションを再利用するため、タグ画面専用の一覧実装による挙動差を増やさない。

### Negative

- 記事一覧を確認するにはタグを一度選択してボトムシートを開く操作が必要になる。
- 非常に長いタグ名は一覧上では省略されるため、完全な名前は選択後のボトムシートヘッダーで確認する必要がある。
- タグセルを高密度化するため、単一列の大きな行より各セルの表示幅は狭くなる。

## Relationship

ADR-0003 の feature 単位のモジュール境界と ADR-0015 の共有 UI プリミティブ再利用方針は変更しない。本 ADR は `:feature:bookmark:ui` 内のタグ探索と選択後詳細表示のインタラクションを具体化する。
