# ADR-0294: RSSフィードごとの手動更新Wi-Fi制限

- Status: Accepted
- Date: 2026-11-03
- Refines: [ADR-0183](0183-rss-settings-tab.md), [ADR-0291](0291-rss-refresh-freshness-and-concurrency.md), [ADR-0292](0292-rss-per-source-refresh-intervals.md)

## Context

手動更新は取得間隔を無視してすべての購読フィードへ通信する。データ量の大きなフィードだけ、モバイル回線での手動取得を避けたい。

## Decision

- RSS設定タブで購読フィードごとに「手動更新はWi-Fi接続時のみ」を切り替えられるようにする。既定値はOFFで、既存購読の挙動を変更しない。
- 設定はRSSが所有する `feeds` テーブルの `manual_wifi_only` 列に保存する。version 43→44で非NULLの既定値0を追加し、既存の購読・自動取得間隔・取得状態を維持する。
- 明示的な手動強制更新の各フィード取得直前に、利用中のネットワークがインターネット接続可能なWi-Fi transportか判定する。未接続または判定不能なら設定ONのフィードをスキップし、HTTP取得を開始しない。対象外のフィードは更新を継続する。
- RSS画面表示時の自動更新、統合バックグラウンド周期更新、OPMLインポート時の初回取得には適用しない。これらの取得条件とアプリ全体のバックグラウンドWi-Fi設定は独立させる。
- スキップを「取得済みの最新状態」と誤解させないように、手動更新結果ではWi-Fi条件によるスキップ数を識別する。
- 新しいWorker・permission・接続監視の常駐処理は導入しない。接続状態は取得判断の時点で参照する。

## Alternatives

- フィードIDごとのSharedPreferences: 削除・復元と購読の同一性管理が二重になるため不採用。
- すべての手動更新を一括でWi-Fi限定: フィード単位で選択したい要求を満たさないため不採用。

## Compatibility and rollback

既存行はOFFになる。既存の通信・画面表示の自動取得、並列制限、排他、HTTPキャッシュ、バックアップを維持する。設定はデータベースsnapshotに含まれる。ロールバック時はデータベースversionの互換性に注意する。

## Verification

フィード単位の選択と永続化、Wi-Fi未接続時の手動スキップ、接続時の取得、他モードの非干渉、件数・表示メッセージ、43→44 migrationを検証する。
