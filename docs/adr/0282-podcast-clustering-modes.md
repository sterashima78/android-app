# ADR-0282: ニュース原稿のクラスタリングモードを比較可能にする

## Status

Accepted

## Context

既存の分類は「同じ具体的な出来事」を単位とする。一方、関連する別の出来事も同じチャプターへまとめ、すべての出来事を原稿へ残す方式を評価したい。既存方式は品質評価まで維持する。

既存の消費済み記事管理では、一度生成した記事を別モードの通常生成へ使えないため、同じ記事snapshotから比較版を生成する専用経路が必要となる。

## Decision

- 番組に既定の分類モード（従来の出来事単位 / 関連トピック単位）を保持する。migration時の既定値は従来方式とする。
- 通常生成・定刻生成は番組の既定モードを使用する。手動生成は別モードを一時指定できる。
- episodeに実際のモードをsnapshotし、生成待ち、失敗後の再試行、中断再開で保持する。
- 完成済みepisodeの保存済み記事snapshotから、別モードの比較版episodeを新規生成できる。比較版は既存の消費済み記事マーカーを変更せず、原本を上書きしない。
- 関連トピック方式は文章embeddingの類似度で分類する。本文の情報を省略しないよう原稿promptを変更する。モデルの処理失敗時は記事を欠落させず1記事1clusterへfallbackする。
- 既存の原稿生成、再生、checkpoint、カテゴリの配線を再利用する。クラスタは全候補のpartitionであり、境界はepisodeに固定する。
- 比較期間中は従来方式を既定値とし、実測後に既定方式を変更する。従来方式の削除は別の判断とする。

## 類似度しきい値の試験調整

関連トピックの類似度は記事集合や埋め込みモデルによって分布が変わり、固定の 0.78 が適切かは未評価である。コード変更を繰り返さず同じ保存済み記事から再生成を試すため、Podcast Context が全番組共通の類似度しきい値を設定として所有する。

- 番組DB columnは増やさず、端末内の `podcast_topic_clustering` SharedPreferences に 0.01 単位のしきい値を保持する。初期値は現行の 0.78 とし、設定を初期化するとoverrideを削除する。
- 設定画面では 0.70 から 0.99 までを変更できる。高い値ほどcomplete-linkの結合条件が厳しくなる。
- 新規cluster生成ごとに設定値を一度読んで固定する。生成待ち、retry、中断再開の保存済みclusterは変更せず、利用者が明示的に作り直したときだけ再評価する。
- 設定ファイルのしきい値キーだけを既存のユーザー設定バックアップallowlistに追加する。埋め込みvectorや評価用の記事ペアは保存しない。
- 評価後に既定値を変更する場合は、別の変更として品質評価結果に基づいて判断する。

## Compatibility

- 旧programとepisodeは従来モードと解釈する。
- 公開するモデルのraw input、embedding vector、推論traceは新しい永続状態として保存しない。
- 利用者が既定モードを変更しても既存episodeのモードとchapter checkpointは変更しない。
