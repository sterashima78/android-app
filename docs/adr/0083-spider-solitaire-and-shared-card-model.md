# ADR-0083: スパイダーソリティアとカードモデル共有

- Status: Accepted
- Date: 2026-08-16

## Context

Game feature には数独とクロンダイクがあり、新たにスパイダーソリティアを追加する。

クロンダイク実装時点では `CardSuit` と `PlayingCard` は `Klondike.kt` に置かれていたが、スパイダーでも同じ52枚トランプの概念を使用する。ゲーム固有ルールまで共通化すると、クロンダイクの赤黒交互ルールとスパイダーの同一スート連続列ルールが混ざり、責務が不明確になる。

## Decision

- `CardSuit` と `PlayingCard` を `:feature:game:domain` の `PlayingCard.kt` へ移し、カードゲーム共通の値オブジェクトとして扱う。
- クロンダイク固有の `TableauCard`、選択状態、山札・捨て札・組札ルールは引き続き `Klondike.kt` が所有する。
- スパイダー固有の場札、選択状態、配札、完成列判定は `Spider.kt` が所有する。
- UI はゲームごとに盤面密度が大きく異なるため、カード描画コンポーネントを現時点では無理に共通化しない。共通化は今後3つ目以降のカードゲームで実際の重複が安定してから判断する。
- スパイダーは 1スート、2スート、4スートの3難易度を提供し、初期値は1スートとする。
- 104枚を使用し、10列へ54枚を配り、残り50枚を10枚ずつ5回配る。
- 場札では同一スートかつ降順の連続列だけをまとめて移動可能とする。移動先はスートに関係なく先頭カードより1つ大きいカード、または空列とする。
- 空列がある間は追加配札を禁止する。
- 同一スートのKからAまで13枚が完成したら自動回収し、8組完成でクリアとする。
- 移動または完成列回収で伏せ札が露出した場合は自動的に表向きにする。
- 進行状態は `SpiderViewModel` が保持し、アプリ終了後の永続化は行わない。

## Consequences

### Positive

- カードの基本表現をクロンダイクとスパイダーで共有できる。
- ゲームごとの合法手判定は独立しており、JVM unit test で検証できる。
- 1/2/4スートを同一実装で扱え、難易度だけを切り替えられる。
- 不要なUI抽象化を避け、スマートフォン上で10列を表示するスパイダー固有の密度調整を行える。

### Negative

- クロンダイクとスパイダーのカード描画には一部重複が残る。
- Undo、ヒント、途中保存、ドラッグ操作は初版では提供しない。

## Relationship

ADR-0080 の Game feature の責務分離と、ADR-0082 のクロンダイクにおけるタップ選択方式を継承する。ADR-0002 の「まず純粋関数でルールを表現する」方針にも従う。
