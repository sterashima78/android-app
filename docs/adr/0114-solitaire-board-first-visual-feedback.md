# ADR-0114: ソリティアは盤面優先表示と合法手フィードバックを持つ

- Status: Accepted
- Date: 2026-08-17
- Updated: 2026-08-24

## Context

ADR-0082 と ADR-0083 では、クロンダイクとスパイダーソリティアの基本操作をタップ選択方式とし、合法手判定を domain に置いた。初版はルール検証を優先したため、Compose UI は固定高の盤面、単純なカード表現、長い説明文を持つ構成だった。

スマートフォンでは7列または10列のカードを扱うため、選択後にどこへ移動できるか分からないと誤タップが増える。また固定高と縦スクロールの組み合わせでは、盤面と操作対象が同時に見えにくい。クロンダイクとスパイダーのUIには、表カード、裏カード、空スロット、選択表現という安定した重複も確認できた。

さらに、縦向きのスマートフォンでは7列・10列の盤面に対してカード幅が小さくなりやすい。横向きではカード幅と列間隔を確保しやすく、盤面優先という本ADRの目的にも合致する。一方、横向き化だけでは縦方向の有効領域が減る。アプリ共通TopAppBar、ゲーム内ヘッダー、操作説明を縦に積むと、横向き端末では場札に割り当てられる高さが不足し、カード下部が画面外へ押し出される。

Android 16では targetSdk 36 以上のアプリについて smallest width が600dp以上の大画面で画面向き要求が原則無視され、Android 17では targetSdk 37 以上でこの大画面方針からの一時的なopt-outも廃止される。そのため、画面向き固定だけをレイアウト成立条件にはできない。

## Decision

- クロンダイクとスパイダーのプレイ画面は縦スクロールを前提にせず、残り領域ではなく利用可能な画面領域そのものを盤面へ割り当てる。
- スマートフォンではクロンダイクとスパイダーのプレイ中に `sensorLandscape` を要求し、左右どちらの横向きでも利用できるようにする。ゲーム一覧や他のゲーム、他機能へ戻る場合は従来どおり縦向きへ戻す。
- Game UI は Android `Activity` を直接操作せず、画面ごとの向き希望を `GameOrientationPreference`、app chrome の表示希望を `GameChromePreference` として app shell へ通知する。`:app` の `GameRouteHost` が向き要求を Android platform へ変換し、`YomitoriApp` が全画面プレイ中だけアプリ共通TopAppBarを外す。
- OSのステータスバーとジェスチャーナビゲーション領域は維持し、アプリ内chromeのみをプレイ中に外す。ゲーム終了操作を失わないよう、戻る操作は盤面内のコンパクト操作として残す。
- クロンダイクとスパイダーでは、従来別行だったゲーム内ヘッダー、手数・完成数、操作説明、山札・組札等の操作を盤面上端の1行へ統合する。通常時の説明文は常設せず、選択中や配札不能時など必要な状態だけ短いフィードバックを表示する。
- 横長画面で余った横幅によってカード自体が過大にならないよう、場札領域にはゲームごとの最大幅を設けて中央配置する。上段の山札・捨て札・組札も固定された小さなカード幅とし、横幅を縦方向のカード高へ無制限に変換しない。
- 場札の重なり幅は利用可能な高さと列内カード数から動的に算出し、横向きでは従来より小さい最小重なり幅を許容する。場札カードはランクとスートを上端で読めるcompact表示を使い、重なりが深い場合でも操作対象を判別できるようにする。
- 画面向き変更によるActivity再生成では、破棄中Activityから縦向き要求を戻さない。通常の画面離脱時だけ縦向きへ復帰し、向き変更の再生成ループを避ける。
- Android 16以降の大画面など、プラットフォームが向き要求を無視する環境では現在のウィンドウサイズに追従して盤面を描画し、横向き固定を前提としない。
- domain は選択中カードから移動可能な場札列・組札を問い合わせる純粋関数を公開する。UIはその結果を使って移動先を強調し、合法手判定を再実装しない。
- 選択中に別の移動不可能な表カードをタップした場合は、そのカードを新しい選択元として扱えるようにする。合法な移動先をタップした場合だけ移動を実行する。
- クロンダイクでは組札へ移動可能な場合、強調表示に加えてコンテキスト操作 `組札へ` を表示する。
- スパイダーの追加配札は山札そのものを操作対象とし、残り配札回数を重ねて表示する。
- 盤面はカードゲーム専用のフェルト調背景、カード面、裏面パターン、影、選択時の拡大、移動可能先の枠を持つ。
- `PlayingCardView`、`CardBackView`、`CardSlotView`、`GameTableSurface` の視覚プリミティブを Game UI 内で共有する。ゲーム固有の盤面レイアウトや操作規則は共有しない。

## Consequences

### Positive

- アプリ共通ヘッダーと重複するゲーム内ヘッダーを除去するため、横向きでも場札に十分な縦方向の領域を割り当てられる。
- 選択後に次の操作先が明確になり、狭いモバイル画面でも誤操作を減らせる。
- 盤面が画面の主要部分を占め、カードゲームとしての視覚的な一体感が高まる。
- 横向きのスマートフォンでは7列・10列の各カードに適切な横幅を割り当てつつ、過大なカード高を避けられる。
- 7列と10列で異なる密度を維持しつつ、カードそのものの見た目は統一できる。
- UIはdomainが返す合法手だけを表示するため、表示とゲームルールの乖離を防げる。
- feature UI は画面向きやアプリ共通TopAppBarの実装詳細を持たず、app shellのplatform/presentation wiring方針を維持できる。

### Negative

- カード描画は固定色を含む専用デザインとなり、アプリ全体のMaterial配色とは一部異なる。
- ドラッグ操作は追加せず、タップ選択を主操作として維持する。
- 盤面を優先するため、長いルール説明はプレイ画面から常設表示しない。
- 横向きプレイ中はアプリ共通のドロワーボタンを表示しないため、別機能へ移動するには盤面内の戻る操作でゲーム一覧へ戻る必要がある。
- カードゲーム開始・終了時にはスマートフォンの画面回転が発生し、Activityが再生成される場合があるため、UI状態は `rememberSaveable` やViewModelで復元可能である必要がある。
- Android 16以降の大画面では横向き要求が保証されないため、レスポンシブな盤面実装を維持する必要がある。

## Relationship

ADR-0082 の「タップ操作を基本とし、合法手判定はdomainが所有する」方針を維持する。ADR-0083 の「盤面レイアウトをゲーム間で無理に共通化しない」方針も維持する一方、2ゲームで重複が安定したカード視覚プリミティブについてのみ共有するため、そのDecisionを限定的に発展させる。加えて、app shellがplatform wiringとアプリ共通chromeを所有する現行アーキテクチャ原則に従い、feature側は向きとchromeの表示意図だけを公開する。
